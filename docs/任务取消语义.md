# 任务取消语义

> 对应 AGENTS.md §5.13.3（Step 接口 / 原子性回滚）/ §5.14.4（临时目录生命周期）/ §0.2-19/21 / 工单 T704。定义「取消一个运行中任务」的完整语义、边界与落地。冲突以 AGENTS.md 为准。

## 1. 单飞模型

- 同一时刻**仅一个**运行中任务（`task.Manager` 持 `running`/`cancel`/`id`，`acquire` 互斥获取）。
- 已有任务在跑时再次发起 → `ErrBusy`（"已有任务运行中"）；前端 preflight 先行拦截，后端为最终裁决（§0.2-14）。
- 入口：`App.Cancel()`（`app.go`）→ `Manager.Cancel()` → 触发当前任务的 `context.CancelFunc`。

## 2. Step 五方法接口（§5.13.3）

```go
type Step interface {
    Name() string
    Execute(ctx, log) error      // 感知 ctx.Done() 提前退出
    Rollback(ctx) error          // 逆序回滚本步骤已做的改动
    Cleanup()                    // 无论成败的收尾（释放句柄等）
    Cancelable() bool            // 该步是否允许被中断
}
```

- `BaseStep` 默认 `Rollback`=nil、`Cleanup`={}、`Cancelable`=false（不可中断步）。
- `FuncStep.Cancelable()` 由构造时的 `Can` 决定；长耗时步（拉镜像、编译、下载升级包）应标 `Cancelable=true` 并在循环内检查 `ctx`。

## 3. 取消流程

```
App.Cancel → Manager.Cancel → cancel()
  → 正在执行的 Step.Execute 观测 ctx.Done() → 返回（ctx.Err()）
  → task 层判定 status = TaskCancelled（§领域模型 4 态之一）
  → 逆序 Rollback（executed[i].Rollback，30s 超时，rollback.go）
  → 清空临时目录：emit cache:tempdir-cleared { reason: "cancelled" }（§5.14.4 第 3 必清）
  → release()：running=false, cancel=nil
  → emit task:done { status: "cancelled", duration }
```

`internal/task/task.go` 在两处 `ctx.Err()` 分支返回 `model.TaskCancelled`（步间与步内），保证取消与「失败」区分：失败走回滚+`failed`，取消走回滚+`cancelled`。

## 4. 取消 vs 失败 vs 回滚

| 触发 | 判定 | 回滚 | 状态 | 临时目录 |
|------|------|------|------|---------|
| 用户取消 | `ctx.Err()==context.Canceled` | 逆序 Rollback | `cancelled` | 清空（reason=cancelled） |
| 步骤报错 | `Execute` 返回 err | 逆序 Rollback | `failed` | 清空（reason=compile_failed 等） |
| 正常完成 | 全部步 `Execute` OK | 不回滚 | `success` | 成功后已提升到缓存再清空 |

- **可恢复性（§5.13.1-6）**：取消后回到操作前状态，不留脏资源（硬红线 8）。
- 回滚本身带 30s 超时，避免回滚步再次卡死；回滚失败会记入审计并报警告，不掩盖原取消意图。

## 5. 临时目录必清（与取消强绑定）

§5.14.4 四必清时机，取消是其一：

1. 编译成功后（提升到缓存后）
2. 编译失败后
3. **任务取消后**（本文）
4. 应用启动时（扫描残留，`app/lifecycle.go` Startup）

每次清空发射 `cache:tempdir-cleared { path, reason }`；`reason` 取值 `compile_success`/`compile_failed`/`cancelled`/`startup_scan`。目的：防止残留污染下次使用（§0.2-21）。

## 6. UI 语义

- 前端 `TaskDrawer` 的「取消」按钮 → `App.Cancel()`；不乐观改状态，等 `task:done(cancelled)` 回流（硬红线 4）。
- 取消期间按钮禁用，避免连点；`Running()` 为真时其它写操作 preflight 报 `ErrBusy` 对应文案。

## 7. 边界

- 不可中断步（`Cancelable()=false`，如落库单事务）在 `Execute` 内不检查 ctx，会跑完当前步再于步间被取消——保证单步原子性优先于即时取消。
- 取消**不撤销**已经完成的其它任务的既成事实；只回滚**本任务**已执行步骤。
- 升级（UpdateApply）取消复用同一机制：marker 未落则下次启动 `rollback.go` 回到旧版本。
