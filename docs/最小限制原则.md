# 最小限制原则

> 对应 AGENTS.md §1.11 / §3.2 原则 7 / §0.2-15/16 / §3.3 硬红线 / 工单 T704。核心：除 8 条硬红线外，所有限制**放开或降级为警告**；能警告的不要阻止。冲突以 AGENTS.md 为准。

## 1. 一句话（§1.11）

> 用户是程序员。软件不替熟练用户做决定；除非违反 8 条硬红线，一律放行。

## 2. 8 条硬红线（§3.3，唯一允许的「阻止」）

| # | 硬红线 | 性质 |
|---|--------|------|
| 1 | PHP 切换精确匹配 `php-{version}-fpm:9000` | 功能准确性刚需 |
| 2 | vhost 写入前必须 `nginx -t` 通过 | 防 nginx 起不来 |
| 3 | 路径穿越 `..` 防御 | 防破坏系统 |
| 4 | 状态同步后端唯一权威 | 一致性刚需 |
| 5 | 三段式写操作 | 事务性刚需 |
| 6 | 升级包 SHA256 + 签名校验 | 供应链安全 |
| 7 | Docker 未装则不能启动服务 | 功能依赖 |
| 8 | Docker 操作清洁 + 离线优先 + 临时目录必清 | 不污染环境 |

**除以上 8 条外，任何限制都必须是「警告」而非「阻止」**（§0.2-16）。

## 3. 放开清单（§2.1 明确排除的限制）

| 维度 | 策略（放开后） |
|------|--------------|
| 密码 | 明文、默认 `123456`、可空、长度/复杂度不校验（[密码策略](./密码策略.md)） |
| 服务版本 | 任意字符串，仅路径安全校验（[版本策略](./版本策略.md)） |
| 域名 | 单段名/任意后缀/泛域名/IDN（[域名策略](./域名策略.md)） |
| 站点根 | 允许在 WWW_ROOT 外（警告，[路径策略](./路径策略.md)） |
| 端口 | 1–65535 全开放；站点端口占用自动顺延不报错（[端口策略](./端口策略.md)） |
| vhost 指令 | 放开 `proxy_pass`/`return`/`rewrite`/`location`/`auth_basic`/SSL/`load_module`（保留硬红线 2） |
| 缓存条目数 | 无上限，用户可手动清理 |

## 4. 警告 vs 阻止的判定（doctor / preflight）

- `DoctorStatus = warn`：可继续（如磁盘 <10GB、Docker 版本旧、站点根越界）。
- `DoctorStatus = err`：仅在触达 8 硬红线或功能不可用时（如 Docker 未装=硬红线 7）。
- preflight 返回值区分 `error`（阻断）与 `warning`（放行 + 提示）；默认能警告就不阻断。

## 5. 例外说明：为什么保留这 8 条

每条硬红线都对应「不阻止会造成不可逆/全局损害」：脏 Docker 状态、半写 vhost 导致 nginx 挂、供应链被投毒、状态漂移导致误操作。其余纯偏好类限制（版本、端口、域名、密码）均无此性质，故全部放开。
