# 离线缓存机制

> 对应 AGENTS.md §1.13 / §3.3 硬红线 8 / §5.14 / 决策 22 / 工单 T704。核心一句话：**装任何镜像/扩展必先查缓存 · 命中零网络 · 镜像未命中先探本机镜像库（已有即零网络重建缓存）· 否则下载编译 · 成功后提升到缓存 · 无论成败均清空临时目录 · 断网重装靠缓存 · 内网开发靠缓存**。扩展一侧缓存的是**包文件本体**（Alpine `apk` 构建依赖 + pecl `.tgz`），安装与重新编译两条路径都必做（§4 / 总纲 §0.2 规则 36）。冲突以 AGENTS.md 为准。

## 1. 三条铁律（§1.13.1）

| # | 铁律 | 落地 |
|---|------|------|
| 1 | 装前必查 | 任何镜像/扩展安装前先查缓存目录（`cache/lookup.go`） |
| 2 | 命中零网络 | 命中 + SHA256 通过 → 直接用，不碰网络，发 `cache:hit`；**扩展的「直接用」指的是包文件本体**——回填容器暂存目录后 `pecl install <包文件>`（§4） |
| 3 | 临时目录必清 | 编译成功/失败/取消/启动残留，四时机必清（[临时目录生命周期](./临时目录生命周期.md)） |

**铁律 2 的补充（AGENTS.md v2.9.6）**：「零网络」不止于缓存命中——缓存丢失但镜像还在本机 Docker 里时（换机、误删 `./offline/`、手工 `docker load` 过），未命中分支先 `ImageExists` 探本机镜像库，命中即 `docker save` 就地重建缓存，同样不碰网络（`cache:miss` 的 `action=local`）；探不到才联网 `docker pull`（`action=pull`）。落地在 `cache/image_cache.go#EnsureImage`，探针接口是 `DockerBackend.ImageExists`（`steps_service.go` 适配 `engine.Client.ImageExists`）。

## 2. 目录结构（§5.14.2，`config/offline.go` 推导）

**缓存根（持久）**：**默认** `./offline/`，可自定义到任意目录（需求 1，AGENTS.md §5.15）。`./` = **PHPO_HOME 根**（装机向导写入 `config.yaml` 的 `phpo_home`，可指向任意目录；`~/phpo` 仅默认值，见 §0.1.1）；自定义值写 `config.yaml` 的 `offline_root`，界面在离线缓存页经 `EditablePathBar` 编辑或选目录。

**互斥唯一**：`offline_root` 非空即完全取代默认根，为空即回落 `{PHPO_HOME}/offline`——**两条缓存根不并存**，所有读写只经 `Env.OfflineRoot` 取（§5.14.12）。

```
./offline/{kind}/{version}/
├── image.tar                    # 基座镜像（docker save 产物）→ 清单记 manifest.image
├── image-extensions.tar         # 扩展固化镜像 phpo/php:{version}（docker commit 产物）→ 清单记 manifest.extensions_image
│                                #   —— 仅 php 有这一份，且与基座**各占一个文件、各一条记录**（v2.9.14，总纲 §5.14.2 / §0.2 规则 35）
├── apk/  pecl/                  # 扩展包本体（仅 php）：pecl 的 {name}-{ver}.tgz + Alpine 基座的 PHPIZE_DEPS .apk
└── manifest.json                # 清单（含 SHA256，schema_version=1）
```

**临时目录（单任务，结束即空）**：`./{kind}/{version}/ext/{apk|pecl}/`——**不可自定义**，恒随 PHPO_HOME（防跨任务污染必须与装机根同生命周期，§5.15.5）。

`Env.OfflineImageTar / OfflineExtImageTar / OfflineManifestFile / OfflineExtDir` 从**当前生效的缓存根**派生（默认或自定义皆同一出口）；`TempExtDir / TempExtTypeDir` 恒从 PHPO_HOME 派生。**三平台同记法**（Windows 亦然），持久值里的 `~` 前缀由 `config.ExpandHome`（`os.UserHomeDir()`）在出口展开（§8）。

## 3. 安装镜像流程（§5.14.3，优先级：离线缓存 > 本机 Docker 镜像库 > 网络）

```
检查 ./offline/{kind}/{version}/image.tar
 ├─ 存在 + SHA256 通过 → docker load（零网络）→ cache:hit → 完成
 ├─ 存在 + SHA256 失败 → 标 cache:corrupted → 落入未命中分支
 └─ 不存在 → 探本机镜像库 ImageExists（探针报错必须上抛，不静默当「没有」）
      ├─ 本机已有 → cache:miss(action=local) → docker save 到 {tmp}（零网络）
      └─ 本机没有 → cache:miss(action=pull) → docker pull → docker save 到 {tmp}
            → 校验 → 提升到 ./offline/…/image.tar + 更新 manifest
            → 清空 {tmp} → cache:promote + cache:tempdir-cleared
```

`lookup.go#LookupImage`（命中前必 `FileSHA256` 校验）→ `image_cache.go#EnsureImage`（未命中先 `ImageExists` 探本机）→ `promote.go#PromoteImage`（`moveFile` mv 临时→缓存 + 登记 `manifest.image`）。

## 3a. 扩展固化镜像的第二槽位（v2.9.14，总纲 §5.14.2 / §5.16.3，需求 ③）

`phpo/php:{version}` 是「容器内编译扩展后 `docker commit`」的产物，**它不是基座**，因此提升到自己的文件
`image-extensions.tar`（`config/offline.go#OfflineExtImageTar`）并在清单里记 `manifest.extensions_image` 一条独立记录。
两个槽位**互不覆盖**：共用即每次「应用扩展」把基座缓存整份抹掉，下次装基座便 load 到内容不符的镜像。

| 能力 | 落点 | 用途 |
|------|------|------|
| `LookupExtImage(version)` | `cache/lookup.go` | 查槽位是否在 + SHA256 校验（损坏则发 `cache:corrupted`） |
| `LoadExtImage(ctx, version)` | `cache/image_cache.go` | 命中即**零网络 `docker load`**，返回载入后的 ref |
| `PromoteExtImage(version, ref, tmpTar)` | `cache/promote.go` | `docker save` 固化镜像到临时目录 → 提升到第二槽位 → 登记清单 |

**零网络恢复路径**（`lifecycle_service.go#specFor`）：php 版本要建容器时先探本机有没有 `phpo/php:{ver}`，
没有就用 `LoadExtImage` 从缓存槽位载回来——从基座建容器会抹掉用户已启用的扩展，而 `php_extensions` 表还记着它们
（总纲 §5.13.1 一致性）。**两处探针报错都上抛**，静默当作「本机没有」等于把抹除过程伪装成一次正常重建（§5.14.12）。

提升成功必须给一行 `ok` **点名落点全路径**（`已提升到离线缓存: {committedRef} → {extTar}`，§5.16.3）——需求 ③ 问的
就是「有没有提升到 offline 下面对应的扩展目录内」，只说「已提升」等于没答。这三个能力**不在 `OfflineService` 门面上**：
它们是安装/恢复链路内部的步骤，不是用户触发的运维动作，故 `App.*` 绑定方法数不因本条增加。

## 4. 安装扩展流程（§1.13.2 / §5.14.3）

**缓存的对象是「包文件本体」，不是扩展名**（总纲 v2.9.14 追加 · §0.2 规则 36）。只缓存编译结果（`.so` / 固化镜像）
等于每次换机、断网重装时 pecl 与 Alpine 构建依赖仍必拨网络；因此 **安装与重新编译两条路径都必须把 apk / pecl 包
落到宿主临时目录并提升到缓存根**。

```
0. 预取构建依赖（仅 added 非空时）：探测基座包管理器 ExtPkgProbeCmd
   ├─ apk（Alpine）→ 先把缓存根 php/{ver}/apk/ 既有 .apk 零网络回填容器 /tmp/phpo-ext/apk
   │                 → 再 apk add --cache-dir /tmp/phpo-ext/apk --virtual .phpo-ext-deps $PHPIZE_DEPS
   │                 → CopyFrom 取回宿主 ./php/{ver}/ext/apk/ → PromoteExtension 登记 manifest.apk
   └─ deb / none   → 一行 dim「构建依赖不产生可离线包文件」，不为它造槽位（官方 Debian 基座的
                      docker-php-ext-install 本就不下系统包）
1. 判类型（apk / pecl）→ LookupExtPackage 按「{name}-」前缀查 ./offline/php/{version}/{type}/
   ├─ 命中 + SHA256 通过 → CopyTo 回填容器 /tmp/phpo-ext/{type}/ → cache:hit(source=offline)
   │                      → pecl 走 `pecl install <包文件>`（零网络）→ 编译 → cache:tempdir-cleared
   └─ 未命中 / 损坏 → cache:miss(action=download)
          → pecl download 到 /tmp/phpo-ext/pecl/ → CopyFrom 取回宿主 ./php/{version}/ext/pecl/
          → PromoteExtension（算 SHA256 + 写 manifest）→ 再从文件编译
          ├─ 成功 → cache:promote
          └─ 失败 → 报错（临时目录仍由 Apply 的 defer 清空）
2. `rm -rf /tmp/phpo-ext` —— **固定在 docker commit 之前**：包文件留在容器层就会被固化进 phpo/php:{version}
3. 宿主临时目录 ./php/{version}/ext/ 由 Apply 的 defer 清空（成败/取消共用一次，reason=compile_ok|compile_failed）
```

- 缓存链**任一环节失败只 `dim` 并退回在线编译**，绝不判死整单（§0.2 规则 16）；`pecl download` 失败即按 `pecl install <name>` 走。
- 前缀匹配是硬要求：pecl 产物名带版本（`redis-6.0.2.tgz`），**按精确名查即永远命中不了**，等于每次白拨一次网络；多份命中取版本序最大的一份（`lookup.go#LookupExtPackage`）。
- 宿主⇄容器唯一字节通道是 Docker archive API：`engine/copy.go` 的 `CopyTo` / `CopyFrom`（php 挂载表里没有 `ext/` 这一档，§4.2 挂载只覆盖源码/conf/logs）。
- 命中裁决仍走 SHA256：`LookupExtension`（精确名，供离线缓存页/单测）、`ListExtPackages`（apk 整目录回填）。清单侧见 [缓存清单规范](./缓存清单规范.md)。

## 5. SHA256 校验（§5.14.5）

- 命中时 / 提升时 / 定期扫描时校验；`cache/verifier.go#FileSHA256`（标准库 `crypto/sha256`）。
- 失败 → 标记损坏 → 发 `cache:corrupted` → 提示用户 → 落入未命中分支（先探本机镜像库，再决定是否联网）。禁止用损坏缓存（§5.14.12）。

## 6. 缓存清理三模式（§5.14.6，`cache/cleaner.go`）

保守（仅损坏）/ 标准（+N 天未用）/ 激进（+所有，除在用）。`inUse` 由已安装服务推导；**清理正在使用的缓存被禁止**（§5.14.12）。入口 `App.CleanupCache` / `OfflineCleanupCache`，发 `cache:cleanup { mode, freed_bytes }`。

## 7. 断网与迁移（§5.14.8/9，画像 F）

- 网络不可达：已缓存的资源照常命中；缓存丢了但镜像还在本机 → `docker save` 零网络重建缓存后照常安装；两者都没有才拒绝安装并提示（`OfflineMissing`/doctor 文案）。**断网重装不要求 `./offline/` 完好无损**。
- 迁移：手动拷贝 PHPO_HOME 根下的 `./offline/`（整目录搬运即保留缓存与 manifest），或备份恢复包含缓存（§5.14.9，见 [备份脱敏规范](./备份脱敏规范.md)）。

### 7.1 三条迁移路径（AGENTS.md §5.14.9 / §5.14.9a）

| 路径 | 做法 | 适用 |
|------|------|------|
| 改根指向既有缓存 | 在离线缓存页把缓存根直接填/选成同事拷来的目录 | 最快；**要求该目录结构与 `manifest.json` 合规**（否则按损坏回退网络） |
| 整目录搬运 | 把源机器的缓存根整体拷到本机缓存根 | 跨机迁移，连 manifest 一起带走 |
| **手工导入单条**（需求 1） | 界面上选 kind / version / 类型（`image`/`apk`/`pecl`）+ 任意路径的文件 → `App.OfflineImportFile` | 只想带一个 `image.tar` 或一个 `.tgz`，不想动整根目录 |

**手工导入的语义（与「提升」相对）**：走 `cache-import` 任务（两步「读取源文件 / 写入缓存」）→ `cache.ImportImage` / `ImportExtension` → `placeFile(keepSrc=true)` **复制**落进当前缓存根并写/更新该版本的 `manifest.json`（算 SHA256）→ 发 `cache:promote`。**原件留在用户选的位置不动**（用户资产，提升才是搬走临时文件）；**不 `docker load`、不建容器**（缓存与 Docker 资源解耦，§5.14.13）；源文件缺失/是目录 → `errs.FileMissing`。

## 8. 服务层 API 与事件

`internal/service/offline_service.go` 实现 §5.14.10 全量接口（`ListCacheEntries/GetCacheEntry/GetCacheStats/VerifyCacheEntry/VerifyAllCache/CleanupCache/RemoveCacheEntry/LookupImage/LookupExtension/PromoteImage/PromoteExtension/ClearTempDir` **+ `ImportEntry`（手工导入，§7.1）**）。**所有路径一律经 `Env.OfflineRoot` 取当前生效缓存根**，自定义根下读写不会落到默认根、反之亦然。事件全表见 [离线缓存协议](./离线缓存协议.md)。

## 9. 明确禁止（§5.14.12 摘要）

装镜像/扩展前不查缓存 · 命中仍走网络 · **把扩展固化镜像提升到基座槽位 `image.tar`（或反之）** · **镜像未命中不探本机镜像库就拨网络** · 命中不校验 SHA256 · 损坏不提示 · 成功不提升 · **成功/失败/取消后不清临时目录** · 启动不扫残留 · 临时目录跨任务持久化 · 静默跳过/清理 · 清理在用缓存。 · **自定义了缓存根却仍读写默认 `./offline/`（两条根并存）** · **手工导入时把用户的源文件搬走**（必须复制保留）· 导入后不发 `cache:promote`、不写 `manifest.json`。

**扩展包本体（总纲 §5.14.12 / §0.2 规则 36，v2.9.14 追加）**：❌ 只缓存「结果」（`.so` / 固化镜像）而不缓存包本体 ·
❌ 命中后仍按扩展名 `pecl install {name}`（等于白拨网络） · ❌ 按精确文件名查缓存（带版本的 `redis-6.0.2.tgz` 永远命不中） ·
❌ apk 预取用 `--no-cache`（用完即弃，拿不到可离线文件） · ❌ 容器暂存目录 `rm -rf /tmp/phpo-ext` 安排在 `docker commit`
**之后**（包文件即被固化进 `phpo/php:{version}` 镜像层） · ❌ 为 deb / none 基座造包缓存槽位或因此判死整单 ·
❌ 缓存链任一环节（查询 · 回填 · 取包 · 取回 · 提升）失败即判死整单——只 `dim` 并退回在线编译。
