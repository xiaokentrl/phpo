# 离线缓存机制

> 对应 AGENTS.md §1.13 / §3.3 硬红线 8 / §5.14 / 决策 22 / 工单 T704。核心一句话：**装任何镜像/扩展必先查缓存 · 命中零网络 · 镜像未命中先探本机镜像库（已有即零网络重建缓存）· 否则下载编译 · 成功后提升到缓存 · 无论成败均清空临时目录 · 断网重装靠缓存 · 内网开发靠缓存**。冲突以 AGENTS.md 为准。

## 1. 三条铁律（§1.13.1）

| # | 铁律 | 落地 |
|---|------|------|
| 1 | 装前必查 | 任何镜像/扩展安装前先查缓存目录（`cache/lookup.go`） |
| 2 | 命中零网络 | 命中 + SHA256 通过 → 直接用，不碰网络，发 `cache:hit` |
| 3 | 临时目录必清 | 编译成功/失败/取消/启动残留，四时机必清（[临时目录生命周期](./临时目录生命周期.md)） |

**铁律 2 的补充（AGENTS.md v2.9.6）**：「零网络」不止于缓存命中——缓存丢失但镜像还在本机 Docker 里时（换机、误删 `./offline/`、手工 `docker load` 过），未命中分支先 `ImageExists` 探本机镜像库，命中即 `docker save` 就地重建缓存，同样不碰网络（`cache:miss` 的 `action=local`）；探不到才联网 `docker pull`（`action=pull`）。落地在 `cache/image_cache.go#EnsureImage`，探针接口是 `DockerBackend.ImageExists`（`steps_service.go` 适配 `engine.Client.ImageExists`）。

## 2. 目录结构（§5.14.2，`config/offline.go` 推导）

**缓存根（持久）**：`./offline/`（`./` = **PHPO_HOME 根**，装机向导写入 `config.yaml` 的 `phpo_home`，可指向任意目录；`~/phpo` 仅默认值，见 AGENTS.md §0.1.1）

```
./offline/{kind}/{version}/
├── image.tar                # Docker 镜像（docker save 产物）
├── apk/  pecl/              # 扩展包（仅 php）
└── manifest.json            # 清单（含 SHA256，schema_version=1）
```

**临时目录（单任务，结束即空）**：`./{kind}/{version}/ext/{apk|pecl}/`

`Env.OfflineImageTar / OfflineManifestFile / OfflineExtDir / TempExtDir / TempExtTypeDir` 全部从 PHPO_HOME 派生：**三平台同记法**（Windows 亦然），持久值里的 `~` 前缀由 `config.ExpandHome`（`os.UserHomeDir()`）在出口展开（§8）。

## 3. 安装镜像流程（§5.14.3，优先级：离线缓存 > 本机 Docker 镜像库 > 网络）

```
检查 ./offline/{kind}/{version}/image.tar
 ├─ 存在 + SHA256 通过 → docker load（零网络）→ cache:hit → 完成
 ├─ 存在 + SHA256 失败 → 标 cache:corrupted → 落入未命中分支
 └─ 不存在 → 探本机镜像库 ImageExists（探针报错必须上抛，不静默当「没有」）
      ├─ 本机已有 → cache:miss(action=local) → docker save 到 {tmp}（零网络）
      └─ 本机没有 → cache:miss(action=pull) → docker pull → docker save 到 {tmp}
            → 校验 → 提升到 ./offline/…/image.tar + 更新 manifest
            → 清空 {tmp} → cache:promote + cache:tempdir-cleared
```

`lookup.go#LookupImage`（命中前必 `FileSHA256` 校验）→ `image_cache.go#EnsureImage`（未命中先 `ImageExists` 探本机）→ `promote.go#PromoteImage`（`moveFile` mv 临时→缓存 + 登记 `manifest.image`）。

## 4. 安装扩展流程（§1.13.2 / §5.14.3）

```
判类型（apk/pecl）→ 查 ./offline/php/{version}/{type}/{package}
 ├─ 命中+校验通过 → 复制到 ./php/{version}/ext/{type}/ → 编译 → 清空 ./php/{version}/ext/ → cache:hit
 └─ 未命中/损坏 → 下载到 ./php/{version}/ext/{type}/ → 编译
      ├─ 成功 → mv ./php/{version}/ext/…→./offline/php/{version}/{type}/ + 更新 manifest + 清空 ./php/{version}/ext/
      │        → cache:miss + cache:promote + cache:tempdir-cleared
      └─ 失败 → 清空 ./php/{version}/ext/ → cache:tempdir-cleared(reason=compile_failed) → 报错
之后：重建固化镜像 phpo/php:{version} + 重启容器（见 ExtApply）
```

`lookup.go#LookupExtension`、`promote.go#PromoteExtension`（`upsertPackage` 写 `manifest.apk/pecl`）。

## 5. SHA256 校验（§5.14.5）

- 命中时 / 提升时 / 定期扫描时校验；`cache/verifier.go#FileSHA256`（标准库 `crypto/sha256`）。
- 失败 → 标记损坏 → 发 `cache:corrupted` → 提示用户 → 落入未命中分支（先探本机镜像库，再决定是否联网）。禁止用损坏缓存（§5.14.12）。

## 6. 缓存清理三模式（§5.14.6，`cache/cleaner.go`）

保守（仅损坏）/ 标准（+N 天未用）/ 激进（+所有，除在用）。`inUse` 由已安装服务推导；**清理正在使用的缓存被禁止**（§5.14.12）。入口 `App.CleanupCache` / `OfflineCleanupCache`，发 `cache:cleanup { mode, freed_bytes }`。

## 7. 断网与迁移（§5.14.8/9，画像 F）

- 网络不可达：已缓存的资源照常命中；缓存丢了但镜像还在本机 → `docker save` 零网络重建缓存后照常安装；两者都没有才拒绝安装并提示（`OfflineMissing`/doctor 文案）。**断网重装不要求 `./offline/` 完好无损**。
- 迁移：手动拷贝 PHPO_HOME 根下的 `./offline/`（整目录搬运即保留缓存与 manifest），或备份恢复包含缓存（§5.14.9，见 [备份脱敏规范](./备份脱敏规范.md)）。

## 8. 服务层 API 与事件

`internal/service/offline_service.go` 实现 §5.14.10 全量接口（`ListCacheEntries/GetCacheEntry/GetCacheStats/VerifyCacheEntry/VerifyAllCache/CleanupCache/RemoveCacheEntry/LookupImage/LookupExtension/PromoteImage/PromoteExtension/ClearTempDir`）。事件全表见 [离线缓存协议](./离线缓存协议.md)。

## 9. 明确禁止（§5.14.12 摘要）

装镜像/扩展前不查缓存 · 命中仍走网络 · **镜像未命中不探本机镜像库就拨网络** · 命中不校验 SHA256 · 损坏不提示 · 成功不提升 · **成功/失败/取消后不清临时目录** · 启动不扫残留 · 临时目录跨任务持久化 · 静默跳过/清理 · 清理在用缓存。
