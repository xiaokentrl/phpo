# 离线缓存机制

> 对应 AGENTS.md §1.13 / §3.3 硬红线 8 / §5.14 / 决策 22 / 工单 T704。核心一句话：**装任何镜像/扩展必先查缓存 · 命中零网络 · 未命中临时下载编译 · 成功后提升到缓存 · 无论成败均清空临时目录 · 断网重装靠缓存 · 内网开发靠缓存**。冲突以 AGENTS.md 为准。

## 1. 三条铁律（§1.13.1）

| # | 铁律 | 落地 |
|---|------|------|
| 1 | 装前必查 | 任何镜像/扩展安装前先查缓存目录（`cache/lookup.go`） |
| 2 | 命中零网络 | 命中 + SHA256 通过 → 直接用，不碰网络，发 `cache:hit` |
| 3 | 临时目录必清 | 编译成功/失败/取消/启动残留，四时机必清（[临时目录生命周期](./临时目录生命周期.md)） |

## 2. 目录结构（§5.14.2，`config/offline.go` 推导）

**缓存根（持久）**：`~/phpo/offline/`

```
offline/{kind}/{version}/
├── image.tar                # Docker 镜像（docker save 产物）
├── apk/  pecl/              # 扩展包（仅 php）
└── manifest.json            # 清单（含 SHA256，schema_version=1）
```

**临时目录（单任务，结束即空）**：`~/phpo/{kind}/{version}/ext/{apk|pecl}/`

`Env.OfflineImageTar / OfflineManifestFile / OfflineExtDir / TempExtDir / TempExtTypeDir` 统一推导，Windows 用 `%USERPROFILE%\phpo\...`（§8）。

## 3. 安装镜像流程（§5.14.3）

```
检查 offline/{kind}/{version}/image.tar
 ├─ 存在 + SHA256 通过 → docker load（零网络）→ cache:hit → 完成
 ├─ 存在 + SHA256 失败 → 标 cache:corrupted → 回退网络
 └─ 不存在 → docker pull → docker save 到 {tmp} → 校验
            → 提升到 offline/…/image.tar + 更新 manifest
            → 清空 {tmp} → cache:miss + cache:promote + cache:tempdir-cleared
```

`lookup.go#LookupImage`（命中前必 `FileSHA256` 校验）→ `promote.go#PromoteImage`（`moveFile` mv 临时→缓存 + 登记 `manifest.image`）。

## 4. 安装扩展流程（§1.13.2 / §5.14.3）

```
判类型（apk/pecl）→ 查 offline/php/{version}/{type}/{package}
 ├─ 命中+校验通过 → 复制到 ext/{type}/ → 编译 → 清空 ext/ → cache:hit
 └─ 未命中/损坏 → 下载到 ext/{type}/ → 编译
      ├─ 成功 → mv ext/…→offline/php/{version}/{type}/ + 更新 manifest + 清空 ext/
      │        → cache:miss + cache:promote + cache:tempdir-cleared
      └─ 失败 → 清空 ext/ → cache:tempdir-cleared(reason=compile_failed) → 报错
之后：重建固化镜像 phpo/php:{version} + 重启容器（见 ExtApply）
```

`lookup.go#LookupExtension`、`promote.go#PromoteExtension`（`upsertPackage` 写 `manifest.apk/pecl`）。

## 5. SHA256 校验（§5.14.5）

- 命中时 / 提升时 / 定期扫描时校验；`cache/verifier.go#FileSHA256`（标准库 `crypto/sha256`）。
- 失败 → 标记损坏 → 发 `cache:corrupted` → 提示用户 → 回退网络。禁止用损坏缓存（§5.14.12）。

## 6. 缓存清理三模式（§5.14.6，`cache/cleaner.go`）

保守（仅损坏）/ 标准（+N 天未用）/ 激进（+所有，除在用）。`inUse` 由已安装服务推导；**清理正在使用的缓存被禁止**（§5.14.12）。入口 `App.CleanupCache` / `OfflineCleanupCache`，发 `cache:cleanup { mode, freed_bytes }`。

## 7. 断网与迁移（§5.14.8/9，画像 F）

- 网络不可达：仅允许用已缓存资源；未缓存的拒绝安装并提示（`OfflineMissing`/doctor 文案）。
- 迁移：手动拷贝 `~/phpo/offline/`，或备份恢复包含缓存（§5.14.9，见 [备份脱敏规范](./备份脱敏规范.md)）。

## 8. 服务层 API 与事件

`internal/service/offline_service.go` 实现 §5.14.10 全量接口（`ListCacheEntries/GetCacheEntry/GetCacheStats/VerifyCacheEntry/VerifyAllCache/CleanupCache/RemoveCacheEntry/LookupImage/LookupExtension/PromoteImage/PromoteExtension/ClearTempDir`）。事件全表见 [离线缓存协议](./离线缓存协议.md)。

## 9. 明确禁止（§5.14.12 摘要）

装镜像/扩展前不查缓存 · 命中仍走网络 · 命中不校验 SHA256 · 损坏不提示 · 成功不提升 · **成功/失败/取消后不清临时目录** · 启动不扫残留 · 临时目录跨任务持久化 · 静默跳过/清理 · 清理在用缓存。
