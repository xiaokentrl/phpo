# 回收站机制

> 对应 AGENTS.md §5.13.7 / §0.3（回收站保留期 7 天）/ §4.2 / 工单 T704。删除类操作不直接物理删除，先进回收站，7 天内可恢复。冲突以 AGENTS.md 为准。

## 1. 定位与动机

「禁止破坏用户数据」（§0.2 / 硬红线相关）：删站点根目录、激进清理涉卷数据时，先把对象**移入**回收站并登记，保留期内可一键恢复，过期才物理删除。

- 目录：`~/.phpo/trash/`（§4.2）。
- 保留期：**7 天**（`store.TrashRetention = 7*24h`，§0.3）。

## 2. 数据模型

`model.TrashEntry`（§领域模型 11）：

```
id · kind · origPath · trashPath · movedAt · expiresAt · expired(是否已过 7 天)
```

登记簿（`internal/store/trash.go`）：
- `AddTrashItem`：`movedAt=now(UTC)`，`expiresAt=movedAt+7天`（未显式给定时）。
- `ListTrash` / `RemoveTrashItem` / `ExpiredTrash(now)`（到期项）。

## 3. 文件操作（`internal/engine/trash.go`）

| 方法 | 行为 |
|------|------|
| `Move(origPath)` | 建 `~/.phpo/trash`（`MkdirAll 0755`）→ `os.Rename` 移入 → 返回 trashPath |
| `Restore(trashPath, origPath)` | 确保原父目录存在 → `Rename` 回原位 |
| `Purge(trashPath)` | 物理删除（仅对到期条目调用） |

跨分区时 `Rename` 可能失败（EXDEV），实现以移动+登记 `origPath↔trashPath` 配对保证可恢复。

## 4. 触发时机与门面

- **删站点**（`SiteRemove`）：根目录入回收站（7 天）→ 删 vhost → 落库删除（`app.go` 注释 §5.13.7）。
- **激进清理**：涉未用卷/数据删除前登记；`CleanupReport.trashPurged` 记录本次顺带清空的到期条目数。
- 门面方法（`app.go`）：`TrashList` / `TrashRestore(id)` / `TrashEmptyExpired`（立即永久删除全部到期项，未满期不动）。
- 前端：`TrashViewer.vue` 列表 + 恢复/清空；删除类操作走 `DangerConfirm` 二次确认。

## 5. 到期清理

- 惰性：任务/清理时顺带 `ExpiredTrash(now)` → `Purge`，并 `RemoveTrashItem` 注销。
- 主动：`TrashEmptyExpired` 一次性清空全部到期条目。
- 未满期条目**永不被自动物理删除**（防误删）。

## 6. 与其它机制边界

| 操作 | 进回收站 | 说明 |
|------|---------|------|
| 删站点根目录 | ✅ | 用户数据 |
| 卸载服务（保留卷） | 卷不动 | 数据卷默认保留（非回收站） |
| 删离线缓存条目 | ❌ | 缓存可重下载，`OfflineRemoveEntry` 直接删 |
| 删 vhost 文件 | ❌ | 非用户内容，直接删 |

审计：入站/恢复/清空均写 `operations.log`（JSON Lines，[资源清洁机制](./资源清洁机制.md) §5）。
