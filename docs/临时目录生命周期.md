# 临时目录生命周期

> 对应 AGENTS.md §5.14.4 / §1.13 / §5.20 / 硬红线 8 / §0.2-21 / §0.2-32 / 工单 T704。临时目录是缓存机制防污染的关键：**单任务存活、四时机必清**；它是 phpo 自己的产出物，故权限 **0777**。冲突以 AGENTS.md 为准。

## 1. 路径（§5.14.2，固定）

```
./{kind}/{version}/ext/      # `./` = PHPO_HOME 根（装机向导写入 config.yaml 的 phpo_home，可指向任意目录）
├── apk/     # 编译期间临时存放
└── pecl/
```

`Env.TempExtDir(kind, version)` / `TempExtTypeDir(kind, version, extType)`（`config/offline.go`）一律从 PHPO_HOME 派生：**三平台同记法** `./{kind}/{version}/ext/`，根位置由装机向导决定（默认值才是 `~/phpo`）；持久值里的 `~` 前缀由 `config.ExpandHome`（`os.UserHomeDir()`）在出口统一展开，Windows 亦适用（§8）。

### 1a. 两条暂存通道（v2.9.14 追加，总纲 §5.14.3 / §5.16.3）

扩展包本体要在**宿主临时目录**与**容器暂存目录**之间来回搬（Docker archive API 是唯一通道：`engine/copy.go` 的 `CopyTo` / `CopyFrom`；php 容器的挂载表没有 `ext/` 这一档）：

| 通道 | 路径 | 谁清 · 何时清 |
|------|------|--------------|
| 宿主临时目录 | `./php/{ver}/ext/{apk\|pecl}/` | `ExtensionService.Apply` 的 `defer ClearTempDir`，**覆盖整条链路**（扩展包取回 + 固化镜像导出），任务退出必清、只发一次 `cache:tempdir-cleared` |
| 容器暂存目录 | `/tmp/phpo-ext/{apk\|pecl}/`（`config.ExtStagingRoot`） | 编译步最后一步 `rm -rf /tmp/phpo-ext`（`ExtStagingCleanupCmd`），**必须排在 `docker commit` 之前** |

容器侧那一条不是「防污染下次任务」而是**防污染镜像层**：包文件留在容器文件系统里就会被 `docker commit` 固化进 `phpo/php:{version}`，那是镜像层垃圾、不是缓存（`ExtStagingCleanupCmd` 只在 `len(added) > 0` 时执行——没有added 就没有写过暂存目录）。

## 2. 四类必清时机（§5.14.4 / §5.14.12）

| 时机 | reason（`cache/tempdir.go` 常量） | 触发方 |
|------|--------|--------|
| 编译成功后 | `compile_ok` | `Apply` 的 defer（`configReasonOK`）／`EnsureImage` 的 defer |
| 编译失败后 | `compile_failed` | `Apply` 的 defer（`configReasonFailed`，含取包/提升任一环节失败）／`EnsureImage` 的 defer |
| 任务取消后 | `cancelled` | `image_cache.go#EnsureImage` 的 defer（`ctx.Err() != nil` 时**取消优先于失败**）；扩展链路自身只带 `compile_ok`/`compile_failed` 两值 |
| 应用启动时 | `startup_scan` | `app/di.go` Startup → `ScanAndClearResidue`；doctor「临时目录残留」项另有只读的 `ScanResidue` |

目的：防止残留污染下次使用（§0.2-21）。四个取值是 `model/cache_entry.go` 的 `Reason` 注释与前端文案的共同判据，**不得**写成 `compile_success`（文档曾有此漂移，本轮校正）。

## 3. 生命周期表（§5.14.4）

| 阶段 | 行为 |
|------|------|
| 任务开始 | `EnsureTempDir` 建 `ext/`（上次残留已由启动扫描或本任务的 defer 清掉） |
| 取包中 | 容器暂存目录 `/tmp/phpo-ext/{type}/`（`pecl download` / `apk add --cache-dir`）→ `CopyFrom` 取回宿主 `ext/{type}/` |
| 编译中 | `CopyTo` 把缓存里已有的包回填容器暂存目录，从**该包文件**编译（命中即零网络） |
| 编译成功（apk/pecl） | 宿主 `ext/{type}/` 的包文件 mv 到缓存根（默认 `./offline/`）的 `php/{version}/{type}/` + 登记 manifest → 清空 `ext/` |
| 编译成功（扩展固化镜像） | `docker save` 产物先落 `ext/image.tar`，再 mv 到 `php/{version}/image-extensions.tar`（**第二槽位**，不动基座 `image.tar`）→ 清空 `ext/` |
| 容器侧收口 | `rm -rf /tmp/phpo-ext`（`ExtStagingCleanupCmd`），**固定在 `docker commit` 之前** |
| 编译失败 | 清空 `ext/` |
| 任务取消 | 清空 `ext/` |
| 任务结束 | 临时目录必然不存在 |
| 应用启动 | 扫描并清空所有残留 |

**两个槽位不可共用**（§5.14.2 / 总纲 v2.9.14 需求 ③）：基座镜像与「基座 + 扩展」固化镜像若都写 `image.tar`，后者会覆盖前者，扩展集从此失去零网络恢复来源（`LoadExtImage` 读的就是 `image-extensions.tar`）。

## 4. 实现（`internal/cache/tempdir.go`）

```go
EnsureTempDir(kind, version)            // util.MkdirAll 建 ext/
EnsureTypeDir(kind, version, extType)   // util.MkdirAll 建 ext/{apk|pecl}
ClearTempDir(ctx, kind, version, reason) // = clearDir
clearDir(path, reason):
    Stat → IsNotExist 视为已清空（仍发射事件，幂等）
    否则 RemoveAll(path) → Emit("cache:tempdir-cleared", {path, reason})
```

对应 §5.14.4 的 `ClearTempDir` 参考实现（不存在即 no-op）。

**权限归一（§5.20 / 总纲 v2.9.14 需求 ②）**：临时目录是 phpo 自己的产出物，建目录一律走 `internal/util/fs.go` 的 `MkdirAll`——**0777**，且对已存在的叶子目录无条件 chmod 自愈。不得回退到 `os.MkdirAll(d, 0o755)`：umask 0022 会把 0777 削成 0755，正是这里曾经踩过的那一档。

## 5. 事件

每次清空发射 `cache:tempdir-cleared { path, reason }`（`model.CacheTempdirClearedEvent`）；前端 `cacheStore` 据此更新展示，并可用于审计/日志抽屉。

## 6. 禁止（§1.13.4 / §5.14.12）

- ❌ 临时目录跨任务持久化。
- ❌ 编译成功/失败后保留临时目录。
- ❌ 任务取消后不清临时目录。
- ❌ 应用启动时不扫描残留。
- ❌ 静默跳过（清空必发事件）。
- ❌ 建临时目录绕过 `util.MkdirAll` 自行传权限位（0777 之外即违反 §5.20）。
- ❌ 把扩展固化镜像提升进基座槽位 `image.tar`（两槽位共用即覆盖基座缓存，§5.14.2）。
- ❌ 在 `docker commit` **之后**才清容器暂存目录 `/tmp/phpo-ext`（包文件即被固化进 `phpo/php:{version}` 镜像层，§1a）。
- ❌ 借「临时目录只清宿主侧」之说跳过容器暂存目录的清理（两条通道各有各的清理时机与理由）。
- ❌ 缓存链任一环节失败即判死整单——只 `dim` 并退回在线编译（总纲 §0.2 规则 16 / §5.16.3）。
