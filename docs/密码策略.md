# 密码策略

> 对应 AGENTS.md §1.5 / §5.2 / §0.2-5/6 / 工单 T704。密码为本项目**明文策略**，禁止任何加密/复杂度/长度校验。冲突以 AGENTS.md 为准。

## 1. 六项规则（§1.5，唯一权威）

| # | 规则 | 说明 |
|---|------|------|
| 1 | 明文存储 | 存于 `config.yaml`（各平台 XDG 用户配置目录内 `phpo` 子目录）的 `services.{kind}.{version}.password`；经快照 `env` 扁平键回显前端 |
| 2 | 默认 `123456` | 新建服务时自动填入（`config.DefaultPassword`） |
| 3 | 可修改 | UI 行内编辑 |
| 4 | 可为空 | 空字符串是合法密码 |
| 5 | 长度不校验 | 1 位、100 位、含特殊字符、含空格均合法 |
| 6 | UI 可查看 | 👁 显示 / 📋 复制 / ↺ 重置 |

## 1.1 生效时机（不属于上述六项规则）

密码经容器 `env` 注入，**只在建容器时落定**：`SetPassword` 只写 `config.yaml` 并广播快照，已运行的容器仍是旧密码——`Start`/`Stop` 不会重注入。要让运行中的服务用上新密码，点版本卡片的「重建生效」（`AppService.Reinstall` → `LifecycleService.Reinstall`，走 §5.13.4 幂等「重装」：Pre-Clean 同名容器 → create → start，**数据卷与宿主目录保留**）。

`PasswordField.vue` 写成功后如实提示「密码已写入 config.yaml……点「重建生效」才会应用到运行中的服务」（`svc.passwordPending`），不假装已切换（硬红线 4：前端不做乐观更新，展示也不得越过事实）。

首次安装是例外：安装弹窗填的密码随 `Install(ctx, kind, version, opts)` 一并带过（`model.InstallOptions.HasPassword` 用来区分「未提供」与「提供空密码」——空密码合法，§1.5），后端在建容器前落 `config.yaml`，容器 `env` 建起来就是它，装好即生效、无需重建。未安装态走不了 `update-config`（要求已安装，否则 `notInstalled`），所以密码不可能「先写后装」。

## 2. 明确禁止（§0.2-5/6、§1.5）

- ❌ 校验密码长度、复杂度、非空。
- ❌ 引入 keyring、Vault、AES、bcrypt、argon2 等任何形式的加密或哈希。
- ❌ 后端对密码做任何规范化（trim 之外不改写大小写/去空格）。
- ❌ 改动密码后不重建容器就宣称运行中的服务已用上新密码（UI 文案与状态不得失真）。

## 3. 落地

- 常量：`internal/config/password.go` → `DefaultPassword = "123456"`；`GenPassword()` 无随机含义，按策略回落默认。
- 读写：`internal/service/env_service.go` 的 `GetPassword` / `SetPassword`（`app.go` 暴露为 `GetServicePassword` / `SetServicePassword`），后端转调 `ConfigStore`。
  - `Get` 未设置时回落 `123456`；`Set` 明文写入，**零校验**，写后广播 `state:changed`（硬红线 4）。
- 存储：`internal/config/configstore.go` 的 `ConfigStore` 门面 → 单一 `config.yaml`（YAML，`0777` 原子落盘，总纲 §5.20）；SQLite 不再持有 `env` 表；`store/snapshot.go` 的 `env` 字段由 `ConfigStore.FlatEnv()` 合成，前端键名契约不变。
- UI：`PasswordField.vue`（👁/📋/↺）；空串通过即时校验，不被前端拦截。

## 4. 与其它策略的关系

- 数据服务（mysql/pgsql/redis）root/默认用户密码走同一明文策略（M5，`db_service.go` / `redis_service.go`）。
- 备份包含 `config.yaml`（内含明文密码）→ 属敏感数据，脱敏与导出边界见 `docs/备份脱敏规范.md`。
- `config.yaml` 文件权限：三平台一律 `0777`（Windows 靠 NTFS ACL）——总纲 §5.20 的裁决是「phpo 自己的产出物不限访问」，本文件**不豁免**（权限位不靠 umask，由 `internal/util/fs.go` 写后显式 `chmod` 归一）。这是文件系统权限，不是内容加密；§0.2 规则 5/6 仍禁止引入任何加密、keyring 或长度校验，也不提供开关。明文密码因此**世界可读**，属既定代价。用例 `internal/config/password_test.go` 锁死落盘即 `0777`。
