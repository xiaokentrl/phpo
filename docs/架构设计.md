# 架构设计

> 对应 AGENTS.md §3.1（工程布局六原则）、§4.1（目录结构）、§12（分层依赖）。冲突以 AGENTS.md 为准。

## 分层与单向依赖

后端严格单向依赖（§3.1 原则 2、§0.2 规则 12「禁止跨层引用」）：

```
装配(app) → 配置(config) → 模型(model) → 存储(store) → 引擎(engine)/缓存(cache)
       → 模板(template) → vhost → 校验(preflight) → 任务(task) → 服务(service) → 更新(updater)
```

上层可依赖下层，**禁止反向或跨层引用**。`internal/` 为私有业务码，`pkg/` 为无业务耦合的通用库。

## 目录分层落点（`internal/`）

| 包 | 职责 | 代表文件 |
|----|------|---------|
| `internal/app` | 依赖注入与启动/关闭钩子 | `di.go`、`assemble.go`、`lifecycle.go`、`emitter.go` |
| `internal/config` | 路径派生、密码/版本/离线策略 | `paths.go`、`password.go`、`versions.go`、`offline.go` |
| `internal/model` | 领域模型与事件载荷 | `service.go`、`site.go`、`cache_entry.go`、`snapshot.go` |
| `internal/store` | SQLite 持久化 + 迁移 | `store.go`、`sqlite.go`、`migrate.go`、`port.go`、`password.go` |
| `internal/engine` | Docker 客户端/容器/镜像/网络/卷/校准/清洁/孤儿/回收站/审计 | `client.go`、`calibrate.go`、`cleaner.go`、`orphan.go`、`audit.go` |
| `internal/cache` | 离线缓存核心（查找/清单/提升/临时目录/校验） | `manager.go`、`lookup.go`、`promote.go`、`tempdir.go`、`verifier.go` |
| `internal/template` | `go:embed` 配置模板 + 渲染 | `embed.go`、`render.go`、`templates/` |
| `internal/vhost` | 站点虚拟主机解析/上游/伪静态/校验/reload + hosts | `manager.go`、`upstream.go`、`rewrite.go`、`hosts/` |
| `internal/preflight` | 后端权威校验（19 action：原型 17 + `root-set`/`cache-import`），由 `app.go` 门面在提交任务前调用 | `preflight.go`、`rules_service.go`、`rules_site.go`、`rules_root.go`、`rules_cache.go` |
| `internal/task` | 三段式任务引擎 + 步骤 | `manager.go`、`task.go`、`funcstep.go`、`steps/` |
| `internal/service` | 各领域服务编排（写走三段式） | `app_service.go`、`lifecycle_service.go`、`site_service.go` |
| `internal/updater` | 应用升级（下载/校验/回滚/安装） | `update.go`、`verifier.go`、`downloader.go`、`rollback.go` |
| `internal/ui` | 窗口/托盘/菜单 | `window.go`、`tray.go`、`menu.go` |

> 说明：自总纲 v2.9.3 起，AGENTS.md §4.1 目录树即仓库真实布局，本文各表的落点与其一致。`internal/i18n` 后端包不存在，前端文案在 `frontend/src/locales/`。

## 通用库（`pkg/`）

| 包 | 用途 |
|----|------|
| `pkg/port` | 端口探测/顺延/建议（`suggest.go`、`sequence.go`、`probe.go`） |
| `pkg/version` | 版本比较（`compare.go`、`semver.go`） |
| `pkg/dockerutil` | 资源命名、镜像引用、等待就绪（`naming.go`、`imageref.go`、`wait.go`） |
| `pkg/archive` | tar.gz 打包/解包（备份用） |
| `pkg/disk` | 跨平台磁盘剩余量（unix statfs / windows） |
| `pkg/errs` | 错误码与包装 |

Docker 资源命名统一经 `pkg/dockerutil`（`phpo-{kind}-{version}` 等），禁止裸写字面量——由 `scripts/check-docker-naming.go` 静态把关。

## 前端架构（`frontend/src/`）

Vue 3.5 + Pinia + Wails Events（§2）。关键约定：

- **状态同步后端唯一权威**（硬红线 4）：`stores/appState.ts` 只经 `composables/useStateSync.ts` 订阅事件回流，无本地乐观更新。见 [状态同步](./状态同步.md)。
- **三段式写操作**（硬红线 5）：`api/*.ts` 经 `useModals.ts` 统一走 preflight→task→applyStateChange。前端的 `usePreflight.ts` 只是即时反馈，**最终裁决由 `app.go` 的 `guard()` 调 `internal/preflight.Run` 兑现**（19 action 全覆盖，漏接即被 `TestGateEveryActionWiredInFacade` 判失败；`Reinstall`/`SiteAddHosts` 例外，见接口契约 §1.1）。见 [接口契约](./接口契约.md)。
- **真实/降级双轨**：写调用以 `hasBackend()` 探测宿主独有字段 `window._wails.flags` / `.environment`（`invoke` 由 `@wailsio/runtime` 在任何 DOM 里都会挂，不可作判据，见 `docs/状态同步.md` §4.1），有 Wails 宿主调真实绑定，否则回退 mock（保纯 vite demo 可跑）。
- 视图 11 个（`views/`）、模态若干（`components/business/`）。界面规格见 [界面规格](./界面规格.md)。

## 装配与生命周期

`internal/app/di.go` 构建真实对象图并挂启动钩子（`lifecycle.go`）：启动时清理残留临时目录（§5.14.4）、执行状态校准（§5.13.9）、启动升级回滚恢复（`updater.RecoverOnStartup`）。
