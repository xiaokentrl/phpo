# 端口策略

> 对应 AGENTS.md §1.9 / §5.8 / §0.3 / 工单 T704。三档行为：**新建站点端口占用先判占用者是不是自家 Nginx——是就复用（照常落盘、照常发布、不提示），确实被别人占着才告警 + 站点降级（vhost 照常落盘，只这一个端口暂不发布；不顺延、不阻断）**，**改已有站点的端口才顺延（不报错）**，**服务端口占用报错**。**降级那句必须说清真因**（rootless 引擎绑不上 <1024 ≠ 被其他程序占用）。冲突以 AGENTS.md 为准。

## 1. 端口行为对照

| 维度 | 新建站点端口 | 改已有站点端口 | 服务端口 |
|------|------------|--------------|---------|
| 默认值 | 80（§0.3） | 站点当前端口 | 各服务标准端口（SVC_META / `versions` 建议） |
| 占用行为 | **先判占用者是不是自家 Nginx**：是（别的站点已把这口交给它发布）就复用——照常落盘、照常发布、按 `server_name` 分流、不提示；不是才**不改用户所填端口**：告警 + 站点降级（**vhost 照常落盘**，只有这一个端口暂不发布） | **顺延 [1,65535] 内首个可用，不报错** | **报 `portInUse`，不顺延** |
| 是否阻断 | 否，站点照常创建 | 否 | 是 |
| 用户指定 | 允许任意 1–65535 | 允许任意 1–65535 | 允许任意 1–65535 |
| 占用者分档 | 四档：① **自家 Nginx 在听**（别的站点已把这口交给它发布）→ 复用，不提示、不降级；② **真被占着**（数据服务的端口，或探针给出 `address already in use`）→ 告警 + 降级；③ **rootless 引擎 + 端口 <1024**（探针是权限不足）→ 告警 + 降级，但那句说的是「引擎绑不上特权端口」并给两条恢复路；④ **其余问不出结果** → 既不阻断也不降级 | 顺延到首个可用端口，不问这四档 | 报 `portInUse`，不顺延 |
| 落点 | **落盘与端口发布解耦**：站点照常落库 + 目录 + hosts + vhost；只有上面「真被占着」与「rootless 特权端口」这两档把这一个端口留在发布集外 | vhost `listen` | 容器端口发布 / 配置 |
| 生效时机 | 写 vhost + `nginx -t` + reload 即生效 | 同左 | **只在建容器时落定**：改端口仅写 `config.yaml`，`Start`/`Stop` 改不动已建容器，必须重建（`Reinstall`）才发布新端口 |
| 自愈 | 腾出该端口后，**任一次站点写操作或 Nginx 启动都会重算一次占用表**——摘掉降级标记并把端口带回发布集（靠重算，不靠重刷已落盘的 vhost 正文） | — | 重建前预检端口占用，冲突即拒绝且不碰正在跑的容器；腾出端口后重建即生效 |

## 2. 权威值（§0.3）

- 可用端口范围：**1–65535**（`MinSupported=1`，`MaxSupported=65535`）。
- 站点默认端口：**80**（`DefaultPort`）。
- 新建站点端口冲突：**不顺延**——先判占用者是不是自家 Nginx（占用表里 owner 以 `site ` 开头，即别的站点已把这口交给它发布）：是就复用，连占用信息都不回传；不是才保留用户所填端口、只回传占用信息，由上层弹框告警 + 站点降级。
- 改站点端口顺延范围：**1–65535 首个可用**，无窗口上限、耗尽不报错。
- 服务端口冲突：报 `portInUse`（`errs.PortInUse`）；不自动顺延。
- 服务端口改动：**不即时生效**——写入 `config.yaml` 后需重建容器（`LifecycleService.Reinstall`）才落到端口发布上；重建在 Pre-Clean 之前做占用预检，冲突则整个操作拒绝、已运行容器原样保留。
- 占用判定唯一来源：`store.CollectUsedPorts(snap, excludeDomains)`（mysql/pgsql/redis 服务端口 + 既有站点端口，先到先得），**不做真实 TCP 探测**。

## 3. 实现（`pkg/port` + `internal/preflight`）

- `Validate(raw, used, Options)`：格式（纯数字、≤5 位）→ 范围（1–65535）→ 排除（`Exclude`，编辑站点自身端口视为空闲）→ 占用判定。三种互斥档位：
  - `Options.KeepOnConflict=true`（**新建站点**）：占用则端口原样返回 `Result{Ok:true, Value, Occupied:true, Msg}`，**不改端口**。
  - `Options.AutoAdvance=true`（**改站点端口**）：占用则 `FindNextAvailable(desired, MaxSupported, MinSupported, used)`（向上优先，再回绕）返回 `Result{Ok, Value, Adjusted:true, Original}`；文案 `errs.PortAdvance`（"端口 {from} 已被占用，自动顺延至 {to}"）。
  - 两者皆 `false`（**服务端口**）：占用直接 `errs.PortInUse`，不顺延。
- `internal/preflight/validators.go`：`portConflict` 枚举 `conflictKeepWarn` / `conflictAdvance` / `conflictBlock` 一一对应上述三档，`validatePort` 据此装配 `Options`。
- `sequence.go#FindNextAvailable`：全范围扫描首个可用，**无窗口上限**（§1.9：去除「耗尽报错」）。
- `probe.go#Probe/Available`：真实 listen 探测，仅备用；站点/服务端口占用一律以账本（`CollectUsedPorts`）为准。

## 4. 落地链路

- 新建站点：`SiteAdd` → preflight `site-add` 先过唯一服务门禁（**Nginx 未安装 = 阻断**，无 nginx 无法发布站点；已装未运行只告警不拦），再以 `conflictKeepWarn` 校验端口——**占用表里 owner 以 `site ` 开头即自家 Nginx 正在听这一口，直接判空闲（复用，连告警都不给）**；剩下的（数据服务端口 / 探针实测到的其他进程）才 `r.warnf` 降级告警（前端 `usePreflight` 同文案 → `DangerConfirm` 弹框）→ 服务层把「能不能写盘」和「要不要发布」拆成两件事：
  - **能不能写盘**（纯函数 `siteLandReady`）：只看「**Nginx 已装** + 所选 PHP 已装」。就绪就写 vhost（`nginx -t` 走运行中的容器）；Nginx 装着但停着则**跳过校验照常落盘**（硬红线 2 的登记例外，见 §5）；Nginx 没装 / PHP 没装才这一轮不写。
  - **要不要发布**（`publishPlan`）：把这一个站点的端口留在发布集外，并给一句「端口 8080 已被 X 占用：站点配置已落盘，只是这个端口暂不发布（腾出后自动补齐）」。站点目录 / vhost / hosts / 落库全部照常，**端口原样保留**、任务不判失败。
- 自愈（`SiteService.ReconcileServe`：逐站点补写**缺失**的 vhost、重算占用表、reload、按发布集重发布端口并广播）：
  - **端口那一档靠重算占用表恢复，不重刷已落盘的正文**——占用腾出来后（卸载冲突服务 / 删掉冲突站点 / 那个进程自己退出），下一次任意站点写操作或 Nginx 启动都会把降级标记摘掉并把端口带回发布集。
  - 服务事件后挂「补齐站点 vhost」步骤（`AppService.healStep`，判定函数 `siteHealedBy(kind, op)`）：**nginx 装 / 重建 / 启动**（这一轮重新 `nginx -t` 校验并补齐未落盘的正文）、**php 装 / 重建**（缺上游的站点有了 fastcgi 目标）、**mysql / pgsql / redis 卸载**（让出被占端口）。php 卸载、nginx 停止只会让站点更降级，补齐必然空转，故不挂。补齐失败只记任务日志不判整个安装任务失败。
  - 站点写操作让出的端口同样要补齐别的站点：`Remove`（删站）与 `writeVHost`（改端口等）在 **Apply 段末尾**走 `healFreed`——步骤阶段库里仍是旧占用表，那时重算会照旧判定「端口被占」而空跑；`healFreed` **不校对宿主端口**（`checkPorts=false`，本次操作已按当轮发布集发布过），只重算降级表；失败只记一行 `task:log` 不上抛。
- **编辑站点的门禁与建站分两档**：`site-port` / `php-switch` / `rewrite` 三处写的是模板生成的配置，过 `nginxServingWarn()`——**Nginx 未安装才报 `nginxNeeded` 阻断；已装未运行只报 `errs.NotRunning: Nginx（站点配置仍会落盘，但未经 Nginx 校验、端口暂不发布；启动 Nginx 后自动重新校验并补齐）` 这一行告警并照常放行**。`site-vhost`（用户手改正文）过 `nginxServing()`，**未运行仍拦**：`errs.NotRunning: Nginx（vhost 改动须经运行中的 Nginx 校验后才能落盘，请先启动 Nginx 再重试）`。理由是手改的那份没有模板兜底，写坏了 Nginx 就起不来，必须先在运行中的容器里过 `nginx -t`；模板生成的那一份坏了可以重新渲染，等 Nginx 起来再校验补齐即可。
- 发布集（`publishPlan`，`publishPorts` 是它读不到快照时的回落）只计入 **vhost 已落盘**的站点端口，并剔除**不是自家站点**的占用：数据服务（mysql/pgsql/redis）已占的端口、以及宿主探针答出「别的进程在用」的端口。降级站点库里仍记着端口，若被后续任一次重发布带给 nginx，容器会去抢绑一个已被占用的宿主端口而绑不上，届时全站瘫痪。**自家站点占的端口不剔除**——那两个站点本来就共用同一个 Nginx 发布口，`server_name` 分流。
- **重发布（`LifecycleService.RepublishNginx`）有两道闸，都在动容器之前**：
  - **未运行即整体跳过**（`engine.Client.ContainerRunning` 按 Docker 实际态判，不看库里的 running 标记）：用户主动停掉（或手工删掉）nginx 后，站点写链路不得把它悄悄拉起并占回宿主端口——那等于替用户决定「nginx 该在跑」。停机期间新写的配置只是**这一轮未经校验**（`siteLandReady` 只要求「已装」），端口等 nginx 下次启动的就绪补齐再绑。
  - **发布集与容器当前绑定一致即不重建**（`sameHostPorts` 比对 `engine.PublishedPorts` 实读值与目标 `spec.PortMap`）：重建等于把整站白闪断一次，而端口校对会被就绪补齐链路反复触发，无差异时必须不动手。
- 就绪入口（`ReconcileServe`）除补 vhost 外**每次都用权威发布集校对一次宿主端口**：停机期间的站点写操作可能压根没发布成功，容器绑的端口集已与站点不符（例如停 nginx 时删了站点，重启后 nginx 仍占着已删站点的宿主端口）。站点写链路自身的 `healFreed` 走 `checkPorts=false`——它已在步骤里按当轮并集发布过，只有真补齐了别的站点 vhost 才再发一次，避免同一次操作把 nginx 重建两遍。
- 改站点端口：`SiteSetPort` → preflight `site-port` 先过 `nginxServing()`（见上）再以 `conflictAdvance` 顺延（排除自身域名与当前端口）→ UI `usePortSuggest` 展示「80→81 已调整」（等后端回流，不乐观，硬红线 4）。
- 装服务 / 改服务配置：服务端口占用报错，用户自行改端口后重试。
- 安装期端口：安装弹窗填的端口随 `Install(ctx, kind, version, opts)` 一次带过（后端先跑 `install` 裁决，占用即 `portInUse` 且**不落任何配置**，通过后才写 `config.yaml` 再建容器）。**不能改成「先 `SetServicePort` 再安装」**——`update-config` 要求版本已安装，未装态会被 `notInstalled` 拦下，等于任何带端口的服务都装不起来（对应原型 `applyStateChange` 的 `type==='install'` 分支）。
- 改服务端口后生效：`EnvService.SetPort` 只落 `config.yaml`（回显立即变、运行态不变）；`ServiceView` 的行内端口保存后提示「端口已写入 config.yaml…点「重建生效」后才会真正切换」（`svc.portPending`）。凡有宿主端口发布的服务（mysql/pgsql/redis/**nginx**）卡片都提供「重建生效」按钮 → preflight `update-config`（**只带 `kind` / `version`，不带 `field`**：重建要判的是「这台容器的端口能不能绑上」，不是「某个字段改得对不对」——密码从未落键、端口在未改过时也可能仍是空键，带 `field=port` 会去读一个不存在的键并必然判失败）→ `AppService.Reinstall` → `LifecycleService.Reinstall`：`assertHostPortsFree` 以 `store.CollectUsedPorts` 判占用（含注册表默认端口补档），冲突在 Pre-Clean **之前**返回 `portInUse`；通过则走与安装同一条幂等管道（Pre-Clean 同名容器 → create（新端口发布）→ start → Post-Verify），数据卷与宿主目录不动。nginx 的基准端口（`NGINX_{VER}_PORT`）与站点端口并集一起发布，同属「只在建容器时落定」这一类，故同样需要重建才生效。
- 未落库端口的**显示**回退：`config.FlatEnv` 只在 `port > 0` 时才吐 `{KIND}_{VER}_PORT`，所以卡片读不到键时不能凭空猜。`ServiceView.portValue` 回退到 `SVC_META.defaultPort`，其值与后端 `registry.Spec.HostPort` 一一对应（php 0＝不发布、mysql 3306、pgsql 5432、redis 6379、nginx 80）。**不得用 `suggestPortFor` 当显示回退**——那是原型给安装弹窗做「填版本就顺手预填端口」的算法（mysql "8.4" → 3384），拿它显示未落库的端口会让界面报一个后端从来没绑过的数字，属失真状态。`suggestPortFor` 的合法用处仅 `InstallModal` 预填。
- 特权端口（80）：Windows 免特权直绑；mac/linux 需 root/setcap，不可绑时由用户换端口（新建站点不再自动顺延）。

## 5. 明确不做

- ❌ 把站点端口硬编码为 80（默认 80，用户可填任意端口，§0.2-17）。
- ❌ 新建站点擅自改动用户所填端口（占用只告警 + 降级，不顺延，§5.8）。
- ❌ 把「别的站点已经把这个端口交给自家 Nginx 发布」当冲突——那是复用（同一颗 Nginx 按 `server_name` 分流），照常落盘、照常发布、不提示、不降级。
- ❌ 因端口占用不写 vhost（**落盘与端口发布解耦**：降级那一档配置照常落盘，只有那一个端口暂不发布，§5.8）。
- ❌ 因端口占用阻止建站（最小限制原则：能警告的不要阻止）；也**不得**因为探针只是问不出结果就阻断或降级——探针是在 phpo 自己进程里 `listen`，量的是 phpo 的权限，不是容器引擎的权限（分档判据收在 `service.ClassifyProbe`）。
- ❌ 把 rootless 引擎绑不上 <1024 特权端口说成「端口 80 已被 其他程序（该端口需管理员权限绑定，无法确认占用者） 占用」——本机并没有别的东西在听这个口，用户按提示去腾端口什么也腾不出来。那句提示必须点名「是 rootless 引擎绑不上」并给两条恢复路：`sudo sysctl -w net.ipv4.ip_unprivileged_port_start=80`（要写进 `/etc/sysctl.d/` 才在下次开机后仍有效），或把站点端口改成 ≥1024；改完任意一次站点保存或重启引擎即自动补发布。**phpo 不替用户动 sysctl、也不改他填的端口**。
- ❌ 因为引擎是 rootless 就把用户填的 80 自动改成 8080（建站弹窗只是把默认预填换成 8080，用户照旧可以填 80；擅自改端口违反 §1.9 端口原样保留）。
- ❌ 拿端口占用当理由去**重刷已落盘的配置正文**（恢复靠重算占用表摘降级标记 + 发布，不靠重新写一遍 conf）。
- ❌ 站点端口耗尽时报错（改站点端口顺延无窗口上限，理论上总有可用位）。
- ❌ 服务端口自动顺延（会与已运行服务冲突而不自知）。
- ❌ 把改服务端口当成即时生效（Docker 端口发布只在建容器时确定；不重建却显示「已生效」属失真状态）。
- ❌ 为了应用新端口先删容器再判占用（端口绑不上等于白丢一个在跑的服务；预检必须在 Pre-Clean 之前）。
- ❌ 限制端口范围（1–65535 全开，§0.2-15）。
