# 端口策略

> 对应 AGENTS.md §1.9 / §5.8 / §0.3 / 工单 T704。两类端口，两套行为：**站点端口占用自动顺延（不报错）**，**服务端口占用报错**。冲突以 AGENTS.md 为准。

## 1. 两类端口对照

| 维度 | 站点端口 | 服务端口 |
|------|---------|---------|
| 默认值 | 80（§0.3） | 各服务标准端口（SVC_META / `versions` 建议） |
| 占用行为 | **顺延 [1,65535] 内首个可用，不报错** | **报 `portInUse`，不顺延** |
| 用户指定 | 允许任意 1–65535 | 允许任意 1–65535 |
| 落点 | vhost `listen` | 容器端口发布 / 配置 |

## 2. 权威值（§0.3）

- 可用端口范围：**1–65535**（`MinSupported=1`，`MaxSupported=65535`）。
- 站点默认端口：**80**（`DefaultPort`）。
- 顺延范围：**1–65535 首个可用**，无窗口上限、耗尽不报错。
- 服务端口冲突：报 `portInUse`（`errs.PortInUse`）；仅站点端口自动顺延。

## 3. 实现（`pkg/port`）

- `Validate(raw, used, Options)`：格式（纯数字、≤5 位）→ 范围（1–65535）→ 排除（`Exclude`，编辑站点自身端口视为空闲）→ 占用判定。
  - `Options.AutoAdvance=true`（站点专用）：占用则 `FindNextAvailable(desired, MaxSupported, MinSupported, used)`（向上优先，再回绕）返回 `Result{Ok, Value, Adjusted:true, Original}`；文案 `errs.PortAdvance`（"端口 {from} 已被占用，自动顺延至 {to}"）。
  - `AutoAdvance=false`（服务/改配置）：占用直接 `errs.PortInUse`，不顺延。
- `sequence.go#FindNextAvailable`：全范围扫描首个可用，**无窗口上限**（§1.9：去除「耗尽报错」）。
- `probe.go#Probe/Available`：真实 listen 探测（逻辑占用表由调用方 `collectUsedPorts` 汇总，探测兜底）。

## 4. 落地链路

- 建站：`SiteAdd` → preflight `site-add` 以 `AutoAdvance=true` 计算端口 → 写 vhost `listen`（nginx -t 必过）→ 落库并广播 `state:changed`。UI `usePortSuggest` + `SiteAddModal` 展示顺延后的实际端口（等后端回流，不乐观，硬红线 4）。
- 改站点端口：`SiteSetPort` → 同样顺延语义（若目标占用）。
- 装服务 / 改服务配置：服务端口占用报错，用户自行改端口后重试。
- 特权端口（80）：Windows 免特权直绑；mac/linux 需 root/setcap，不可用则顺延到首个可绑端口（§8）。

## 5. 明确不做

- ❌ 把站点端口硬编码为 80（默认 80，占用即顺延，§0.2-17）。
- ❌ 站点端口耗尽时报错（无窗口上限，理论上总有可用位）。
- ❌ 服务端口自动顺延（会与已运行服务冲突而不自知）。
- ❌ 限制端口范围（1–65535 全开，§0.2-15）。
