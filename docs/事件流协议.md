# 事件流协议

> 对应 AGENTS.md §5.6（事件协议）/ §0.2-10（状态同步后端唯一权威）/ §3.2（前后端通信）/ 工单 T704。事件名与载荷以本文表为准；后端发射器 `internal/app/emitter.go`，前端唯一订阅通道 `frontend/src/api/events.ts` + `composables/useStateSync.ts`。冲突以 AGENTS.md 为准。

## 1. 通信模型

- **单向权威**：所有状态由后端计算 → 发射事件 → 前端订阅回流。前端**从不本地乐观更新**（硬红线 4）。
- **通道**：Wails 3 Event（`application.App.Event.Emit`）。`app.go` 的 `wailsEmitter` 是 `internal/app.Emitter` 到 Wails 事件系统的适配；未注入 Wails 实例时 `Emit` 静默丢弃（测试/启动早期）。
- **计数**：协议事件共 **17** 个（`ALL_EVENTS` 对账须恰为 17）。另有 `ui:command` 为**前端 UI→UI 本地广播**（托盘/命令面板触发，不经后端），不在这 17 之内。

## 2. 事件全表（§5.6）

### 2.1 状态类

| 事件 | 载荷 | 时机 |
|------|------|------|
| `state:changed` | `{ snapshot }` | 后端状态变化后（任何写操作落地的最终回流） |
| `service:changed` | `{ kind, version, running }` | 单服务运行态变化 |

### 2.2 任务类

| 事件 | 载荷 | 时机 |
|------|------|------|
| `task:log` | `{ id, level, text }` | 任务输出一行（`level` ∈ 5 类，见 §领域模型） |
| `task:progress` | `{ id, step, total }` | 步骤进度变化 |
| `task:done` | `{ id, status, duration }` | 任务结束（`status` ∈ running/success/failed/cancelled） |

### 2.3 升级类

| 事件 | 载荷 | 时机 |
|------|------|------|
| `update:available` | `{ version, changelog, size }` | 发现新版本 |
| `update:progress` | `{ stage, percent, speed }` | 升级进度（stage：download/verify/install） |
| `update:done` | `{ status, version }` | 升级完成 |

### 2.4 Docker 清洁类

| 事件 | 载荷 | 时机 |
|------|------|------|
| `docker:cleanup` | `{ stage, resource, action }` | 清理进度 |
| `docker:orphan-found` | `{ resources: []Resource }` | 孤儿扫描发现 |
| `docker:state-drift` | `{ expected, actual }` | 校准检测到漂移 |

### 2.5 离线缓存类（§5.14.11）

| 事件 | 载荷 | 时机 |
|------|------|------|
| `cache:hit` | `{ kind, version, source, size }` | 命中缓存（零网络） |
| `cache:miss` | `{ kind, version, action }` | 未命中缓存 |
| `cache:promote` | `{ kind, version, entries }` | 提升到缓存 |
| `cache:corrupted` | `{ kind, version, entry }` | SHA256 校验失败 |
| `cache:cleanup` | `{ mode, freed_bytes }` | 缓存清理完成 |
| `cache:tempdir-cleared` | `{ path, reason }` | 临时目录已清空（4 个必清时机，§5.14.4） |

> 载荷 JSON 标签以后端 `internal/model/` 事件结构体为准（见 [领域模型](./领域模型.md)）；`cache:cleanup` 用 `freed_bytes`，`cache:tempdir-cleared` 的 `reason` 取值为 `compile_success` / `compile_failed` / `cancelled` / `startup_scan` 等语义串。

## 3. 典型事件时序

### 3.1 安装服务（缓存未命中）

```
App.Install → preflight OK → task.Pre-Clean
  → pull → save → verify → 提升 → 清空临时目录
      emit cache:miss → cache:promote → cache:tempdir-cleared
  → 容器装配 → Post-Verify → applyStateChange
      emit task:progress* → service:changed → state:changed → task:done
```

### 3.2 安装服务（缓存命中）

```
App.Install → preflight → lookup+SHA256 OK
  emit cache:hit → docker load → 容器装配
  emit service:changed → state:changed → task:done   # 无网络、无 promote
```

### 3.3 取消

```
App.Cancel → manager 触发 context 取消 → 正在跑的 step 感知 ctx.Done
  → 逆序 Rollback（30s 超时）→ 清空临时目录 emit cache:tempdir-cleared(reason=cancelled)
  → emit task:done(status=cancelled)
```

## 4. 前端订阅契约

- `api/events.ts` 导出 `EVENT` 常量（与 `internal/app/emitter.go` 一一对应，**禁止漂移**）与 `ALL_EVENTS` 对账数组。
- `useStateSync.ts` 统一注册订阅，把 `state:changed` 写入 `appState` store，`task:*`/`cache:*`/`update:*` 分派到对应 store；视图只读 store，不各自订阅。
- 断线/刷新后靠 `GetState()` 兜底拉全量（见 [接口契约](./接口契约.md) §2），保证「后端唯一权威」不因前端生命周期丢失。
