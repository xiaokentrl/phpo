# 接口契约

> 对应 AGENTS.md §0.2（三段式写操作 / 后端唯一权威）/ §5.5–§5.9 / §5.13 / §5.14.10 / 工单 T704。本文描述前端可调用的**唯一绑定入口** `app.go` 的 `*App` 门面方法契约，以及所有写操作必须遵守的三段式与 preflight 前置。冲突以 AGENTS.md 为准。

## 1. 契约总则

1. **唯一入口**：`app.go` 的 `*App` 是 `wails3 generate bindings` 暴露给前端的**全部**方法；前端不直接触达 `internal/`。
2. **未就绪守卫**：`AppService`/各子服务为 nil 时统一返回 `errNotReady`（"服务尚未初始化"），防止启动钩子完成前抢跑。
3. **后端唯一权威（硬红线 4）**：读方法即时返回权威态；写方法成功后由后端发射 `state:changed`，前端订阅回流，**不做本地乐观更新**。
4. **三段式写操作（硬红线 5）**：所有写操作走 `preflight() → task.Manager（Pre-Clean → Execute → Post-Verify）→ applyStateChange`。其中第一段的**最终裁决已接进后端**：`app.go` 的 `guard(action, Ctx)`（内部 `runGuard`）在 `errNotReady` 守卫之后、提交任务之前调 `preflight.Run`，非 `Ok` 即返回错误、任务不创建。详见 §1.1。

5. **生命周期**：`Attach(app, window)` 注入 Wails 实例与主窗口并装托盘（窗口必须先建：托盘点击与「关闭时最小化」都要绑到它）；`ServiceStartup()` 执行启动钩子（含残留临时目录清理 + 状态校准）；`ServiceShutdown()` 收尾。

### 1.1 后端最终裁决（§0.2 #14）

- **接线位置**：`app.go`。校验层在 `internal/preflight/`，按 §3.1 原则 2 的单向依赖链排在 `task`/`service` **之上**（… → 校验 → 任务 → 服务 → 更新），所以 `service` 反向 import 校验层即违反 §0.2 #12——门神只能落在门面这一层，前端 `usePreflight.ts` 由此回归「仅即时反馈」的定位。
- **覆盖范围**：§0.3 冻结的 **17 个 action 全部有调用点**（18 个站点，`restore` 同时服务 `BackupRestore`）。`TestGateEveryActionWiredInFacade` 读 `app.go` 源码逐一对账，漏接或新增未接线的 action 即失败。
- **裁决输入取自权威快照**：`runGuard` 先 `GetState()` 拿 `*model.Snapshot` 组装 `preflight.World`，占用表与前端镜像同源（`store.CollectUsedPorts`）；不另立判据。
- **只消费 `Errors`**：`Warnings` 一律不阻断（§0.2 #16），其展示仍由前端镜像负责；`Adjusted`（站点端口顺延结果）后端不消费，写路径本就用同一张占用表重新派生，两套标准反而会漂移。
- **附属清单按需读取**：备份/缓存清单只在真消费它们的 action（`restore`、`backup-delete`、`offline-prune`）才读，读取失败只让该 action 失败闭合，不影响 `install` 等无关写操作。
- **被拒时的前端表现**：真实宿主下任务由后端执行、经事件回流，`start()` 只登记等效命令并展开抽屉，因此后端拒绝不会留下「运行中」的幽灵记录，直接以 toast 呈现裁决文本。
- **刻意不接的两处**：`Reinstall`（§3：裁决是「未安装即拒 + 新端口在 Pre-Clean 前判占用」，由 `LifecycleService.Reinstall` 就地兑现，且 17 条里没有「重装」这个 action）、`SiteAddHosts`（§4：唯一前置是站点存在，无端口/路径/版本可裁决）。

## 2. 生命周期与信息

| 方法 | 契约 |
|------|------|
| `AppInfo() map[string]string` | 返回 `{name:"phpo", version}`，确认绑定链路已通 |
| `GetState() (*Snapshot, error)` | 拉取当前权威快照（订阅外的兜底读） |
| `Running() bool` | 是否有任务执行中（单飞判据；排队项不计） |
| `Cancel()` | 取消当前运行中任务（清空临时目录，见 §5.14.4） |
| `CancelQueued(id string) bool` | 撤回**尚未执行**的排队项；`false`=已移交执行或不存在，调用方不得据此改本地状态 |
| `SetTrayPrefs(showTray, minimizeOnClose bool) error` | 把两项托盘偏好投影到原生外壳（撤/挂托盘图标 + 关闭窗口驻留或退出）。**UI 偏好的权威仍是 `localStorage`**（§3.1 原则 5），后端不反向读取、不落 `config.yaml`/SQLite，故是快照外的唯一例外；托盘未安装（`Attach` 前）返回 `errNotReady`。**不过 preflight**：17 个 action 已冻结且其语义无端口/路径/版本可裁决，三段式（硬红线 5）约束的是业务状态写操作 |

任务队列详情不是方法而是快照字段：`GetState()`/`state:changed` 的 `tasks{ running, pending }`（`model.TaskBoard`）。历史任务读 `OperationList(limit)` 中带 `taskId` 的行（见 §6.5）。

## 3. 服务生命周期（M3）

`Install (ctx, kind ServiceKind, version string, opts InstallOptions) error` + `Reinstall / Start / Stop / Remove (ctx, kind ServiceKind, version string) error` + `Calibrate(ctx) error`。

- `Install`：缓存优先镜像（§5.14.3）→ 容器装配；幂等（先清理同名/冲突资源）。`opts{ port, password, hasPassword }` 是**安装期配置**：端口与密码只在「建容器那一刻」被 spec 读走，而 `update-config` 要求版本已安装（未装态报 `notInstalled`），所以二者必须由 `Install` 携带——门面先跑 `install` 裁决（端口占用即 `portInUse`，不顺延，§5.8），通过后才落 `config.yaml`（`services.{kind}.{version}.{port,password}`），再进任务链建容器。`hasPassword` 用于区分「未提供」与「提供空密码」（空密码合法，§1.5）；`port<=0` 视为未提供，不写脏值。安装弹窗里填的 PHP 扩展是另一条链路：安装任务之后再发一个 `ExtApply` 任务（容器内编译 → 固化 `phpo/php:{ver}` → 重建）。
- `Reinstall`：**重建容器**，把只有建容器时才落定的配置送进去——宿主端口发布 + 密码 `env`（§5.13.4 幂等「重装」）。与 `Install` 共用镜像准备/落盘/建容器三段，差别只在末段走 `LifecycleService.Reinstall`。两条前置裁决：① 快照 `Installed` 里没有该版本即拒（Docker 里有裸容器不算已装）；② **占用预检在 Pre-Clean 之前**——以 `store.CollectUsedPorts` 判 mysql/pgsql/redis 的发布端口是否被占（含注册表默认端口补档），冲突返回 `portInUse` 且**不碰任何容器**，避免"已删旧容器却绑不上新端口"。数据卷与宿主目录保留。
- `Stop`：停止但保留数据；`Remove`：卸载容器**保留数据卷**（删卷需 §5.13 二次确认路径）。
- 全部经 `AppService → task.Manager` 三段式；失败自动回滚。`Install / Start / Stop / Remove` 分别接 `install`、`service-start`、`service-stop`、`uninstall` 四个 action 的后端裁决（§1.1）。**不新增 preflight action**（§0.3 冻结 17 条）：重建复用 `update-config`（`field=port`）的占用裁决，最终裁决仍在 `Reinstall` 的 Pre-Clean 之前。

## 4. 站点（M4）

| 方法 | 契约要点 |
|------|---------|
| `SiteAdd(ctx, AddInput)` | 幂等建站：建目录 → 写 vhost（**nginx -t 必过**，硬红线 2）→ 加 hosts → 发布端口 → 落库并广播 `state:changed`。任一步失败按逆序回滚，**含撤下本步刚写入的 hosts 条目**（站点没建成就不留解析；「已存在跳过」的条目不算本次改动，回滚不动它） |
| `SiteRemove(ctx, domain)` | 根目录入回收站（7 天）→ 删 vhost → **回收该域名的 hosts 条目** → 落库删除。回收步骤失败只降级为警告（提权被拒等，与 `SiteAddHosts` 同口径），不判整个删除任务失败；回滚时把条目重新加回 |
| `SiteSetPort(ctx, domain, port)` | 写 vhost `listen` + nginx -t → 落库；端口 1–65535 |
| `SiteSwitchPHP(ctx, domain, php)` | 上游精确 `php-{version}-fpm:9000`（硬红线 1），10 步流程（§5.5） |
| `SiteSetRewrite(ctx, domain, preset, rule)` | 伪静态预设（9 种）+ 自定义规则 |
| `SiteSetVhostContent(ctx, domain, content)` | 手改并保存 vhost 正文，落库前 nginx -t 必过 |
| `SiteAddHosts(ctx, domain)` → `(warning string, err error)` | 手动补写系统 hosts（站点列表「加 hosts」）。**首返回值是人话警告不是错误**：空串=已生效或本就幂等；非空=未落盘原因（如「请以管理员身份运行」），按 §3.2 原则 7 降级为提示、`err` 仍为 `nil`。仅 `hosts` 文件 IO 真失败才回 `err`。走 `task.Manager` 三段式（硬红线 5），`Apply` 段广播快照，`site.hosts` 由后端探针回流（硬红线 4）。**不新增 preflight action**（§0.3 冻结 17 条）：唯一前置是站点存在，无端口/路径/版本可裁决 |

## 5. 数据服务 env 与配置（M5）

| 方法 | 契约要点 |
|------|---------|
| `GetServicePassword / SetServicePassword` | 明文密码读写；未设置回落默认 `123456`；**空串/任意长度合法，零校验零加密**（§5.2） |
| `GetServicePort / SetServicePort` | 服务宿主发布端口读写；服务端口占用报 `portInUse`，不自动顺延（§5.8）。`Set` 只落 `config.yaml`，**运行中的容器不变**（端口发布只在建容器时定），生效需 `Reinstall`（§3）。两个 `Set` 均接 `update-config`（`field` 分别为 `password` / `port`）的后端裁决：服务未安装即拒，端口占用即拒（§1.1） |
| `ConfigGetFiles(kind, version) ([]template.File, error)` | 宿主已存在则回显内容，否则回落模板默认 |
| `ConfigSaveFiles(ctx, kind, version, files)` | 原子保存：备份原文件 → 写入 → 失败自动回滚（路径穿越防御，硬红线 3） |

## 6. 扩展 / 备份 / doctor / 升级 / 清理 / 缓存 / 向导（M6）

### 6.1 扩展
- `ExtList(version) ([]string, error)`：读当前启用集（后端权威）。
- `ExtApply(ctx, version, enabled)`：容器内编译 → commit 固化 `phpo/php:{version}` → **提升离线缓存 → 清空临时目录**（§5.14）→ 重建容器 → 重载 nginx。启用集与当前一致时直接返回，不产生任务也不重建。
  - **php 的装配镜像按本机实际态现取**（`LifecycleService.specFor`，安装与重建共用）：`ImageExists(phpo/php:{version})` 为真就用固化镜像，否则才用基座 `php:{version}-fpm`。若一律用基座，装/重建一次 php 就把用户已启用的扩展静默抹掉，而 `php_extensions` 表还记着它们（违反 §5.13.1 一致性）。探针报错**必须上抛**，静默当成「本机没有」等于把这次抹除伪装成正常重建（§5.14.12 禁止静默）。
  - **编译失败的回滚目标同样现取**：原启用集非空且固化镜像真在本机才回滚到固化镜像，镜像已被手工删除/换机没带过来则退回基座——否则回滚的第一步建容器就 `No such image`，用户连「重新点一次扩展」这条恢复路都没有（§5.13.1 可恢复性）。

### 6.2 备份
- `BackupList()` / `BackupPath(file)` / `BackupSaveAs(file, dst)`：列表与导出（`file` 仅接受合法文件名，防穿越）。
- `BackupCreate(ctx)`：暂停数据服务 → 导出 SQLite 快照 → 打包 → 自动重启。
- `BackupRestore(ctx, file)`：清空命名空间 → 解包落盘 → 逻辑重放 SQLite → 重建容器。
- `BackupDelete(ctx, file)`：删除归档（二次确认在前端）。

### 6.3 doctor
- `DoctorRun(ctx) (DoctorReport, error)`：§5.7 的 15 项检查 + 汇总计数。
- `DoctorFix(ctx, id)`：一键修复（`calibrate` / `clear_temp`），幂等可重复。

### 6.4 升级
- `UpdateCurrentVersion() string`、`UpdateCheck(ctx) (UpdateAvailable, bool, error)`。
- `UpdateApply(ctx)`：经任务引擎串行执行（下载 → **SHA256+Ed25519 双校验** → 备份 → 安装，失败回滚，硬红线 5/6）；进度走 `update:progress/done`；前面有任务则排队，同标签重复提交回 `ErrQueued`。

### 6.5 清理与回收站
- `CleanupScan(ctx)`：全量孤儿扫描并广播 `docker:orphan-found`。
- `CleanupRun(ctx, mode)`：三模式删除孤儿；激进涉卷删除由前端二次确认。
- `CleanupCache(ctx, mode)`：三模式清理离线缓存（在用受保护）。
- `TrashList` / `TrashRestore(ctx, id)` / `TrashEmptyExpired(ctx)`：7 天回收站。
- `OperationList(limit)`：最近审计历史（文件权威见 `operations.log`）。

### 6.6 离线缓存（§5.14.10 全量 API）
`OfflineListEntries` / `OfflineGetEntry` / `OfflineStats` / `OfflineVerifyEntry` / `OfflineVerifyAll` / `OfflineCleanupCache` / `OfflineRemoveEntry` / `OfflineLookupImage` / `OfflineLookupExtension` / `OfflinePromoteImage` / `OfflinePromoteExtension` / `OfflineClearTempDir`。
- 命中前一律先校验 SHA256；损坏发射 `cache:corrupted`。
- `OfflineClearTempDir(ctx, kind, version, reason)` 清空临时目录并发射 `cache:tempdir-cleared`。

### 6.7 装机向导
- `HomeVerify(ctx, home, www)`：**只读预检**——校验路径安全、判存在、按权限位判可写；**不创建任何目录、不写探测文件、不落库、不发事件**。尚不存在但最近已存在祖先可写的条目报「○ …（确认后将创建）」。
- `HomeEnsure(ctx, home, www)`：**目录与文件的唯一创建入口**（用户点「确认并创建」才触发）——先决检测 `Configured()`：两根「已持久化 + 目录实际存在」即为已设置，一律跳过创建、不改写 `config.yaml`（即便本次请求路径与已设目录不同，也不建第二套工作目录），仅广播权威快照令 UI 归位；未设置才走三段式创建工作目录子树（`MkdirAll` + 试写探测）并把两根目录落地 `config.yaml`，随后广播 `state:changed`（`dirReady` 不落库，由快照按「两根已持久化 + 目录实际存在」派生；两根一旦落地即解锁运行态库的延迟创建）。
- `HomeDefaults()`：返回 `PHPO_HOME` / `WWW_ROOT` 预填值（`config.yaml` 已存根 > `~/phpo` 默认）+ `CONFIGURED`（`"true"`/`"false"`）——向导挂载即读，`CONFIGURED=true` 时只回显已设两根与「完成」，不进入三步设置流程。
- `Restart()`：重建对象图的唯一手段——各服务在装配期按值持有展开后的两根（`internal/app/di.go`），会话中途改根无法靠刷新快照归位，只能按 `config.yaml` 重启重建。置 `restartPending` 后 `Quit()`，实际拉起在 `ServiceShutdown` 释放资源后由 `relaunchSelf()` 以子进程完成，并带环境标记 `PHPO_RESTARTED=1`；带标记的第二代再被请求重启即拒绝报错，防「刷新失败→重启」无限循环。
- 刷新优先、重启兜底：前端 `useStateSync.ts#syncState()` 是「主动拉取权威快照」的公共入口（启动、手动同步、装机向导完成/已设置态四处复用，与 `state:changed` 走同一 `applySnapshot`，硬红线 4）。工作目录设置完成或检测到已设置时**第一件事**就是 `syncState()` 令主界面与弹框同一时刻归位；同步后 `homeReady` 仍为 false 才升级请求 `Restart()`。
- 判据统一：`Configured()` 与快照 `dirReady` 双 true 同源（`ConfigStore.RootsReady()`），前端 `homeReady` 与后端拦截共用一套标准，不另立判据。

## 7. preflight 契约（唯一裁决层）

所有 action 在执行前先过 `internal/preflight/preflight()`；UI 层即时校验不替代它（§0.2-14）。

**17 个 action（§0.3 权威值）**，分三组：

| 组 | action |
|----|--------|
| service（6） | `install` `uninstall` `service-stop` `service-start` `update-config` `service-config` |
| site（6） | `site-add` `site-remove` `site-port` `site-vhost` `php-switch` `rewrite` |
| ops/cache（5） | `extensions` `backup` `restore` `backup-delete` `offline-prune` |

- `ActionCount = 17`、`NeedsHomeCount = 15` 为对账测试常量。
- **NEEDS_HOME（15）**：除 `php-switch` 外的 action 需 `PHPO_HOME`（`dirReady`）就绪，否则返回 `NEEDS_HOME`（引导装机向导）。
- 校验遵循最小限制：能警告不阻止；除 8 条硬红线外一律放行（§0.2-16、§3.3）。

## 8. 返回值约定

- 错误经 `pkg/errs` 包装，携带可 i18n 的 code（如 `portInUse`、`TASK_BUSY`、`NEEDS_HOME`）；`hint` 为人话文案（§3.2 原则 3）。
- 写方法返回 `error`；查询方法返回 `(T, error)`；事件载荷见 `docs/事件流协议.md`。
