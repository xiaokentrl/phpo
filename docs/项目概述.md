# 项目概述

> 对应 AGENTS.md §1（定位与核心结论）。本文为总纲的展开说明；**任何与 AGENTS.md 冲突处，一律以 AGENTS.md 为准**。

## 一句话定义

**phpo** 是一款面向 PHP 开发者的本地 Docker 化开发环境管理器，跨 Windows / macOS / Linux 三平台，**仅提供 GUI 桌面应用，不提供 CLI**（AGENTS.md §1.1、§0.2 规则 4）。

## 差异化定位

对标 Laravel Herd / Laragon / phpStudy，phpo 以「Docker 多版本化」替代之。核心差异（§1.1）：

- 多 PHP × 多 DB 版本并存；
- 中文框架预设；
- 一键备份迁移；
- **最小限制**原则（仅 8 条硬红线，其余一律放行或降为警告）；
- **Docker 操作清洁**（幂等、原子、可回滚、可清理）；
- **离线优先**（装任何镜像/扩展必先查缓存，命中零网络）。

## 技术栈（冻结，§2）

| 层级 | 选型 | 版本约束 |
|------|------|---------|
| 桌面框架 | Wails | ≥ 3.0 |
| 后端语言 | Go | ≥ 1.27 |
| 前端框架 | Vue + TS + Vite | Vue 3.5+ / TS 5.x / Vite 5.x |
| 状态管理 | Pinia | 2.x |
| 持久化 | SQLite（pure Go，`modernc.org/sqlite`） | CGO_ENABLED=0 |
| 容器引擎 | Docker SDK（`docker/docker/client`） | — |

技术栈禁止漂移（§0.2 规则 3）：不得以「更轻」「更易」为由替换框架。布局契约见 [目录规范](./目录规范.md)。

## 真实用户画像（§0.4）

产品以「真实开发者工作流」为标准，服务七类画像：

| 画像 | 占比 | 关键场景 |
|------|------|---------|
| A 外包/接单 | ~50% | 反复装卸 PHP 版本、内网/弱网 |
| B 小团队负责人 | ~30% | 新同事首次装机、团队内网 |
| C 独立开发者/学习者 | ~20% | 反复试验、网络不稳定 |
| D 高级/黑客型 | ~10% | 完全掌控 Docker 环境、手动清缓存 |
| E 自动化/CI | ~5% | 无人值守反复操作 |
| F 内网/弱网/离线 | ~5% | 完全依赖离线缓存、断网重装 |

## 核心结论（§1.3）

单文件 HTML 原型（`单文件 HTML 原型（前端唯一界面来源）`）不是「演示稿」，而是**可执行规格**，生产功能完成度约 **60–70%**（§1.2）。领域模型与校验层真实可用，执行层与持久层为虚构，本项目将其真实化。

## 三条贯穿性策略

1. **端口策略**：站点端口默认 **80**，被占用则在 **1–65535** 内顺延首个可用（不报错、无窗口上限）；服务端口占用仍报 `portInUse`。详见 [端口策略](./端口策略.md)。
2. **密码策略**：明文存储、默认 `123456`、可修改、可为空、长度不校验、UI 可查看。详见 [密码策略](./密码策略.md)。
3. **应用升级**：支持版本检查与自动升级，升级包 **SHA256 + 签名双校验**。详见 [应用升级](./应用升级.md)。

## 8 条硬红线（§3.3）

除下列 8 条外，所有限制放开或降级为警告（详见 [最小限制原则](./最小限制原则.md)）：

1. PHP 切换精确匹配 `php-{version}-fpm:9000`；
2. vhost 写入前必须 `nginx -t` 通过；
3. 路径穿越 `..` 防御；
4. 状态同步后端唯一权威；
5. 三段式写操作；
6. 升级包 SHA256 + 签名校验；
7. Docker 未装则不能启动服务；
8. Docker 操作必须清洁 + 离线优先 + 临时目录必清。

## 里程碑（§10）

M0 规格冻结 → M1 骨架 → M2 底座 → M3 服务线（PHP+Nginx）→ M4 站点闭环 → M5 数据服务 → M6 运维面 → M7 发布。M0–M7 全部完成，交付物见 [打包发布](./打包发布.md)。
