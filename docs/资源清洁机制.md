# 资源清洁机制

> 对应 AGENTS.md §1.12 / §5.13.5–§5.13.10 / 工单 T704。聚焦「清洁」：孤儿扫描、三模式清理、操作前后自检、审计日志。冲突以 AGENTS.md 为准。

## 1. 孤儿资源扫描（§5.13.5）

- 时机：启动时 + 每 24 小时 + 手动（`App.CleanupScan`）。
- 判定：`engine/orphan.go` 纯判定函数（输入 Docker 资源集 + 权威快照 → 输出孤儿）；`Client` 负责采集（`engine/inspect.go`）。
- 分类：容器 / 卷 / 网络 / 镜像（`model.OrphanReport`），发现即广播 `docker:orphan-found { resources }`。
- 默认**保留卷**（用户可确认删除）；**不扫描离线缓存**（缓存与 Docker 资源解耦，§5.14.13）。

## 2. 三模式清理（§5.13.6）

`App.CleanupRun(ctx, mode)`（`model.CleanupMode`，§领域模型 5.1）：

| 模式 | 清理内容 | 适用 |
|------|---------|------|
| conservative 保守 | 仅已停止/无主且明显垃圾 | 日常 |
| standard 标准 | 保守 + 未使用镜像/悬空 | 定期 |
| aggressive 激进 | 标准 + 未使用卷（**涉卷删除需前端二次确认**，§5.13.7 关联回收站） | 释放空间 |

返回 `model.CleanupReport { mode, items[], removed, failed, freedBytes, trashPurged }`。缓存清理是**独立**入口 `CleanupCache`（§5.14.6，见 [离线缓存机制](./离线缓存机制.md)）。

## 3. 操作前后自检（§5.13.8，CI 无人值守）

- 操作前：Pre-Clean 检查同名/冲突资源并抹平（[Docker操作规范](./Docker操作规范.md) §4）。
- 操作后：`engine/verify.go` Post-Verify 确认达成态；不符则回滚。
- 支持画像 E：每次运行环境干净，非交互下亦可安全执行。

## 4. 状态校准（§5.13.9）

`engine/calibrate.go`：启动 + 每次任务后 + 手动。检测 Docker 实际态与 SQLite 记录漂移 → `docker:state-drift { expected, actual, gaps }`；`App.Calibrate` / doctor `fix:"calibrate"` 修正。

**手动「同步状态」是全量口径**（v2.9.14，总纲 §5.19）：除运行态外，还逐个已安装版本核**容器 / 基座镜像 / 扩展固化镜像**三样存在性，缺席以派生 `Snapshot.Gaps`（`model.ServiceGap`，三种 `reason`）点名——服务卡片显示缺失 pill、抽屉逐行说明缺了哪一样。**绝不自动改写 `installed`、不自动删建资源**：第三方工具删容器不等于用户要卸载，配置/卷/缓存都在，用户点「启用」即按当前配置幂等重建（固化镜像不在本机时由 `LoadExtImage` 从缓存槽位零网络 `docker load` 回来）。发事件闸门是 `len(corrections)==0 && sameGaps(...)`，**不得**用 `res.Changed()`（容器缺席是常态化，否则每次同步都刷屏）。

## 5. 操作审计日志（§5.13.10）

- 路径：`<用户数据目录>/logs/operations.log`（Linux `~/.config/phpo/logs/`），**JSON Lines**（一行一条，`engine/audit.go#AuditLine` 纯函数序列化，写盘与单测复用）。
- 载荷 `model.Operation { ts, actor, op, args, status, durationMs, error? }`：`actor ∈ ui/system`（无 CLI），`op` 为 8 幂等操作名之一，`status ∈ success/failed/cancelled`。
- UI 展示经 `App.OperationList(limit)`（读 `operations` 表）；**文件为权威**，表为查询缓存。
- 每次清理/删除同时登记回收站（§5.13.7）。

## 5.1 全量资源清理面板（AGENTS.md §5.22）——与上面三套的关系

**一句话**：本节那三套（孤儿扫描 / 三模式清理 / 回收站）都**原样保留**；新面板只是多了一个**全量口径的入口**，删除仍然走同一批底层实现，不另起第二套（需求 ⑨）。

| 对比项 | 孤儿扫描 + 三模式清理 | 60 行全量清理面板 |
|--------|----------------------|-------------------|
| 看的东西 | 只有 phpo 命名空间（`phpo-` 前缀，§5.13.3 隔离性） | **全量**：包括用户自己用 docker CLI / Docker Desktop / compose 建的东西 |
| 什么时候动手 | 按模式一批删 | 勾行 → **先看逐项预览** → 一次清空（一个任务、逐项一行、单颗失败不中断其余） |
| 有数据的东西 | 卷默认保留（§0.2 规则 20） | 先挪进回收站留 7 天（`volume.data` 等 **5** 行）；**phpo 自己的卷挪不动就不删** |
| 宿主上的文件 | 不碰 | 要管理员授权才读、才删（那 19 行），五种删法各有失败原因 |
| 删除实现 | `internal/engine`（container/volume/image/network…） | **同一处**：`clean_delete.go`（Docker 侧九类）+ `clean_hostdel.go`（宿主侧五种），循环语义共用 `runDeletes` |

**面板删掉 phpo 自己的容器/镜像之后界面显示什么**：只让服务卡片显示**缺失态**（§5.19 那套 `gaps`），`installed` 这本账**不动**；确认框里那颗「同时卸载这些版本」默认不勾，勾了也要等删除任务返回之后**另起一单**（任务里嵌套提交即 `ErrBusy`）。

## 6. 与回收站/缓存的边界

| 场景 | 清洁机制 | 回收站 | 离线缓存 |
|------|---------|--------|---------|
| 卸载服务 | 删容器，**保留卷** | 不涉及 | **不动缓存** |
| 重建服务（改端口/密码后「重建生效」） | Pre-Clean 抹同名容器 → 重建，**卷与宿主目录复用**；占用预检在 Pre-Clean 之前，冲突即不碰容器 | 不涉及 | **优先命中缓存** |
| 删站点 | 删 vhost + 回收该域名的 hosts 条目（失败仅警告、回滚时加回） | 根目录入回收站（7 天） | 不动 |
| 激进清理 | 可删未用卷 | 删前登记 | 可选清理（用户确认） |
| 状态校准 | 修漂移 | 不动 | **不动缓存** |

关键约束：缓存不受 Docker 清洁机制影响；Docker 资源与缓存完全解耦（§5.14.13）。
