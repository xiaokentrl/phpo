# 资源清洁机制

> 对应 AGENTS.md §1.12 / §5.13.5–§5.13.10 / 工单 T704。聚焦「清洁」：孤儿扫描、三模式清理、操作前后自检、审计日志。冲突以 AGENTS.md 为准。

## 1. 孤儿资源扫描（§5.13.5）

- 时机：启动时 + 每 24 小时 + 手动（`App.CleanupScan`）。
- 判定：`engine/orphan.go` 纯判定函数（输入 Docker 资源集 + 权威快照 → 输出孤儿）；`Client` 负责采集（`engine/inspect.go`）。
- 分类：容器 / 卷 / 网络 / 镜像（`model.OrphanReport`），发现即广播 `docker:orphan-found { resources }`。
- 默认**保留卷**（用户可确认删除）；**不扫描离线缓存**（缓存与 Docker 资源解耦，§5.14.13）。

## 2. 三模式清理（§5.13.6）

`App.CleanupRun(ctx, mode)`（`model.CleanupMode`，§领域模型 5.1）：

| 模式 | 清理内容 | 适用 |
|------|---------|------|
| conservative 保守 | 仅已停止/无主且明显垃圾 | 日常 |
| standard 标准 | 保守 + 未使用镜像/悬空 | 定期 |
| aggressive 激进 | 标准 + 未使用卷（**涉卷删除需前端二次确认**，§5.13.7 关联回收站） | 释放空间 |

返回 `model.CleanupReport { mode, items[], removed, failed, freedBytes, trashPurged }`。缓存清理是**独立**入口 `CleanupCache`（§5.14.6，见 [离线缓存机制](./离线缓存机制.md)）。

## 3. 操作前后自检（§5.13.8，CI 无人值守）

- 操作前：Pre-Clean 检查同名/冲突资源并抹平（[Docker操作规范](./Docker操作规范.md) §4）。
- 操作后：`engine/verify.go` Post-Verify 确认达成态；不符则回滚。
- 支持画像 E：每次运行环境干净，非交互下亦可安全执行。

## 4. 状态校准（§5.13.9）

`engine/calibrate.go`：启动 + 每次任务后 + 手动。检测 Docker 实际态与 SQLite 记录漂移 → `docker:state-drift { expected, actual }`；`App.Calibrate` / doctor `fix:"calibrate"` 修正。

## 5. 操作审计日志（§5.13.10）

- 路径：`~/.phpo/logs/operations.log`，**JSON Lines**（一行一条，`engine/audit.go#AuditLine` 纯函数序列化，写盘与单测复用）。
- 载荷 `model.Operation { ts, actor, op, args, status, durationMs, error? }`：`actor ∈ ui/system`（无 CLI），`op` 为 8 幂等操作名之一，`status ∈ success/failed/cancelled`。
- UI 展示经 `App.OperationList(limit)`（读 `operations` 表）；**文件为权威**，表为查询缓存。
- 每次清理/删除同时登记回收站（§5.13.7）。

## 6. 与回收站/缓存的边界

| 场景 | 清洁机制 | 回收站 | 离线缓存 |
|------|---------|--------|---------|
| 卸载服务 | 删容器，**保留卷** | 不涉及 | **不动缓存** |
| 删站点 | 删 vhost | 根目录入回收站（7 天） | 不动 |
| 激进清理 | 可删未用卷 | 删前登记 | 可选清理（用户确认） |
| 状态校准 | 修漂移 | 不动 | **不动缓存** |

关键约束：缓存不受 Docker 清洁机制影响；Docker 资源与缓存完全解耦（§5.14.13）。
