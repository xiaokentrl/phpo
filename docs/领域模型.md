# 领域模型

> 对应 AGENTS.md §0.3 / §4.1（`internal/model/`）/ 工单 T704。所有模型为**纯数据结构**（JSON 标签即前端绑定契约），零业务逻辑；状态字段的唯一权威在 `internal/store/`（硬红线 4）。冲突以 AGENTS.md 为准。

## 1. 服务（`service.go`）

| 类型 | 说明 |
|------|------|
| `ServiceKind` | 服务种类字符串；`AllKinds` = **5** 种（§0.3）：`php` / `mysql` / `pgsql` / `redis` / `nginx` |
| `InstalledVersion` | 某服务某版本的安装态：`kind` / `version` / `running` |

约束：版本开放输入（仅路径安全校验，§5.4）；Nginx 为单例服务（`NginxSingleton()`）；`running` 由 Docker 实际状态校准得出，前端不做乐观推断。

## 2. 站点（`site.go`）

`Site{ domain, port, php, root, rewrite, rewriteRule?, vhostCustomized?, hosts, health }`

- `port`：站点端口，默认 80，用户可任意指定；新建时占用**不顺延**——站点以降级态创建（vhost 暂不落盘、端口暂不发布），改已有站点的端口才在 1–65535 内顺延首个可用（§5.8）。
- `php`：该站点使用的 PHP 版本，切换时上游精确为 `php-{version}-fpm:9000`（§5.5，硬红线 1）。**可以为空**（降级站点未选 PHP）：列表渲染「未选择」占位项，已装列表里不存在的版本追加「（未安装）」后缀，前端不把空值伪装成某个版本。
- `rewrite`：伪静态预设名；`rewriteRule` 在 `preset==custom` 时存自定义规则原文。
- `vhostCustomized`：标记 vhost 被用户手改过（此后不再自动覆盖正文）。
- `hosts` / `health`：**展示用运行态，不落库**。由 `Store.BuildSnapshot()` 出口逐站点按宿主真值派生（`hosts` 走注入的 `HostsProbe`；`health` 走 `SiteRuntime.Health()`：nginx 未运行或 vhost 未落盘 = `warn` 降级；就绪但 PHP 未运行或站点目录已不在 = `down` 未响应；否则 `up`）。列表的健康列与 Hosts 列只能来自这两个字段，前端不得自行推断（硬红线 4）。
- `URL()`：展示地址；端口 443 时 scheme 为 `https`，否则 `http`。

## 3. 任务与日志（`task.go`）

| 类型 | 取值 / 字段 |
|------|-----------|
| `TaskStatus` | **4** 态（§0.3）：`running` / `success` / `failed` / `cancelled` |
| `LogLevel` | **5** 类日志行（§0.3）：`cmd` / `meta` / `ok` / `dim` / `err` |
| `LogLine` | `{ level, text }` |
| `TaskLogEvent` | `{ id, level, text }` → 事件 `task:log` |
| `TaskProgressEvent` | `{ id, step, total }` → 事件 `task:progress` |
| `TaskDoneEvent` | `{ id, status, duration }` → 事件 `task:done`（`duration` 是 Go `time.Duration`，JSON 为**纳秒**） |
| `TaskBrief` | `{ id, label, type, kind, version, domain, step, total, startedAt }` → 面板上的一条任务摘要。`kind` / `version` / `domain` 由 `model.TaskMeta` 同名字段带入（`briefOf`），**服务类任务带 `kind`+`version`、站点类任务带 `domain`**，其余（备份、清理等）留空。服务卡片按 `(kind, version)`、站点行按 `domain` 亮「执行中 / 等待中」指示，不按 `label` 文案反推 |
| `TaskBoard` | `{ running *TaskBrief, pending []TaskBrief }` → 队列详情，挂在 `Snapshot.Tasks`（**不落库**，随 `state:changed` 推送） |

任务执行走三段式 Pre-Clean → Execute → Post-Verify（§5.13.3，硬红线 5）。`task.Manager` 串行 FIFO：一次只跑一个，其余排队；排队态是**分区**（`pending`）而非第 5 个任务状态（§0.3 冻结 4 态）。终态由 `internal/task/ledger.go` 落 `operations` 账本（§7）。

## 4. 全局快照（`snapshot.go`）

`Snapshot` 是后端向广播前端的**唯一权威状态载体**（`state:changed` 载荷、`store/snapshot.go` 序列化目标）：

```
installed      map[kind][]version   # 已安装
running        map[kind][]version   # 运行中
sites          []Site
env            map[string]string    # 派生路径 + 服务密码/端口等
phpExtensions  map[phpVer][]ext
dirReady       map[string]bool      # PHPO_HOME / WWW_ROOT 就绪标记（**派生量**：config.yaml 两根已持久化 + 目录实际存在，不落 SQLite）
tasks          TaskBoard            # 任务队列详情（running + pending，Manager 的队列快照）
```

## 5. 离线缓存（`offline.go` + `cache_entry.go`）

### 5.1 视图/结果模型（`offline.go`）

| 类型 | 用途 |
|------|------|
| `CacheEntry` | 缓存条目（`kind/version/path/hasImage/apkCount/peclCount/totalSize/lastVerify/verifyOk`） |
| `CacheStats` | 总览（`totalBytes/entryCount/imageCount/extCount/corrupted`） |
| `CleanupMode` | **3** 模式（§5.14.6）：`conservative` / `standard` / `aggressive` |
| `CleanupResult` | `{ mode, freedBytes, removed }` |
| `VerifyResult` / `VerifyAllResult` | 单条 / 全量 SHA256 校验结果 |
| `ImageCacheResult` / `ExtCacheResult` | 命中查询返回（`hit/path/size/corrupted`） |

### 5.2 缓存清单 `manifest.json`（`cache_entry.go`，§5.14.2）

```
CacheManifest{ schema_version=1, kind, version, created_at, updated_at,
               image?, apk[], pecl[] }
ManifestImage{ name, digest, size, sha256, cached_at }
ManifestPackage{ name, sha256, size, cached_at }
```

`schema_version` 固定为 **1**；校验方式 **SHA256**；缓存条目数上限**无限制**（§0.3）。`scripts/check-cache-manifest.go` 对上述 JSON 标签键集做静态对账。

### 5.3 缓存事件载荷

`CacheHitEvent{kind,version,source,size}` · `CacheMissEvent{kind,version,action}` · `CachePromoteEvent{kind,version,entries}` · `CacheCorruptedEvent{kind,version,entry}` · `CacheCleanupEvent{mode,freed_bytes}`（事件名见 §5.6 表）。`cache:tempdir-cleared` 载荷为 `{ path, reason }`。

## 6. Docker 资源与漂移（`resource.go`）

| 类型 | 说明 |
|------|------|
| `ResourceType` | `container` / `volume` / `network` / `image` |
| `DockerResource` | `{ type, id, name, size?, inUse }` |
| `OrphanFound` | `{ resources[] }` → 事件 `docker:orphan-found` |
| `OrphanReport` | 按四类分组的扫描报告 |
| `StateDrift` | `{ expected, actual }` → 事件 `docker:state-drift` |

命名规范（§5.13.2）：容器 `phpo-{kind}-{version}`、网络 `phpo-network`、卷 `phpo-{kind}-{version}-{purpose}`。

## 7. 操作审计（`operation.go`）

`Operation{ ts, actor, op, args, status, durationMs, error?, taskId?, label?, logs? }`

- `actor` 固定为 `ui` 或 `system`（本产品无 CLI，§5.1）。
- `op` 为 8 个幂等操作名之一（install / uninstall / start / stop / reinstall / site-add / site-remove / import，§5.13.4）。
- `status` 复用 `success / failed / cancelled`。
- `taskId / label / logs` 三项是**任务账本**扩展（迁移 `0008_add_task_ledger.sql`）：由任务引擎在每个三段式任务终态统一写入，`logs` 为该任务日志原文（换行分隔，**尾部保留 500 行**），`error` 即失败原因。UI「历史任务」= `OperationList` 中 `taskId` 非空的行。
- 落地：`<用户数据目录>/logs/operations.log`（JSON Lines；Linux `~/.config/phpo/…`）+ `operations` 表。

## 8. 备份（`backup.go`）

`BackupFile{ file, size, at, items }` — 归档列表项；`items` 为归档顶层内容组数。备份归档位于 PHPO_HOME 根下的 `./backups/backup-*.tar.gz`（`./` 随装机向导所选位置，非固定 `~/phpo`），含 SQLite 快照与配置/数据目录，脱敏规范见 `docs/备份脱敏规范.md`。

## 9. 应用升级（`update.go`）

| 类型 | 字段 |
|------|------|
| `UpdateAvailable` | `{ version, changelog, size }` → `update:available` |
| `UpdateProgress` | `{ stage(download/verify/install), percent, speed }` → `update:progress` |
| `UpdateDone` | `{ status, version }` → `update:done` |

升级包必须 SHA256 + Ed25519 双校验（硬红线 6，§5.9）；检查频率为启动时 + 每 24 小时。

## 10. 环境诊断（`doctor.go`）

- `DoctorStatus`：`ok` / `warn`（可继续）/ `err`（可能阻断）。
- `DoctorCheck{ id, title, status, detail, hint, fix }`；`fix` 取值 `""` / `"calibrate"` / `"clear_temp"`。
- `DoctorReport{ checks[], ok, warnings, errors }`，覆盖 §5.7 的 15 项检查。

体现最小限制原则：**能警告的不要阻止**（§0.2-16）。

## 11. 清理与回收站（`cleanup.go`）

| 类型 | 说明 |
|------|------|
| `CleanedItem` | `{ type, name, ok, error? }` |
| `CleanupReport` | `{ mode, items[], removed, failed, freedBytes, trashPurged }` |
| `TrashEntry` | `{ id, kind, origPath, trashPath, movedAt, expiresAt, expired }`，保留期 **7 天**（§5.13.7） |

## 12. DTO（`dto.go`）

服务层出入参传输对象（如 `AddInput`、`ConfigFile`、`HomeVerifyResult` 等）集中于此，避免把持久层实体直接暴露给绑定层。字段命名与前端 TS 绑定保持一致（`json` 标签即契约）。
