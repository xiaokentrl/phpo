# 路径策略

> 对应 AGENTS.md §5.12 / §3.3 硬红线 3 / §4.2 / 工单 T704。核心：**允许站点根在 WWW_ROOT 之外（降级为警告）**，但路径穿越（`..`）是硬红线，任何平台一律拦截。冲突以 AGENTS.md 为准。

## 1. 两类路径，两套规则

| 类别 | 规则 | 违反后果 |
|------|------|---------|
| **安全底线（硬红线 3）** | 禁 `..` 独立段 / 空段 / `\x00` | error，阻断 |
| **位置约定（最小限制）** | 站点根默认在 `WWW_ROOT` 内 | 越界仅 warning，放行 |

## 2. 实现（`internal/config/validate.go`）

- `NormPath`：trim → 折叠 `//` → 去尾 `/`（原型 `normPath` 直译）。
- `HasTraversal`：正则 `(^|/)\.\.(/|$)` 命中独立 `..` 段即真 → `errs.PathTraversal`。
- `ValidateSiteRoot(root, wwwRoot)`：
  1. `NormPath` 后为空 → `errs.RootEmpty`。
  2. `HasTraversal` 命中 → `errs.PathTraversal`（硬红线 3）。
  3. 不在 `wwwRoot` 子树内 → `RootCheck{Ok:true, OutsideWww:true}` + `errs.RootOutsideWww`（**警告，放行**，§5.12）。
  4. 在子树内 → `Ok:true`。

> 关键：`OutsideWww` 是 `Ok` 的一个标志位而非 error——「能警告的不要阻止」（§0.2-16）。

## 3. 目录派生（`internal/config/paths.go`，原型 `derivePaths`）

- `PHPO_HOME`（记法 `./`，默认值 `~/phpo`）派生各服务 `./{kind}/{version}/{conf,data,logs,initdb}` 子树、`./backups/`、`./offline/`（§4.2 / AGENTS.md §0.1.1）。密码/端口/两根本身存于 `<用户数据目录>/config.yaml`（= `os.UserConfigDir()/phpo`），**不在 PHPO_HOME 下、不随装机向导移动**。
- `WWW_ROOT`（默认值 `~/www`）派生站点根 `<WWW_ROOT>/<domain>/`；它是独立于 PHPO_HOME 的另一根，故不用 `./` 记法。
- `~` 前缀的展开与平台无关：`config.ExpandHome`（`os.UserHomeDir()`）在出口统一展开（Windows 无 shell `~`，同样走这条路径），用户数据目录另由 `config/userdata.go` 按 OS 规则解析（§8）。

## 3.1 可自定义根（AGENTS.md §5.15，需求 1/2/7/8）

三类根**同一判据、同一出口**：`ValidateRootPath`（即 `checkRootPath`）只做路径安全（`NormPath` + 穿越/`\x00` 拦截），**不要求绝对路径、不要求目录已存在、不限字符集**（最小限制，§0.2-15/16）。空串是合法值且语义为「清除自定义」。

| 根 | `config.yaml` 键 | 默认位置（未自定义时） | 唯一生效出口 |
|----|------------------|----------------------|-------------|
| 离线缓存根 | `offline_root` | `{PHPO_HOME}/offline`（记法 `./offline/`） | `config.ApplyRootOverrides` → `Env.OfflineRoot` |
| 备份归档根 | `backup_root` | `{PHPO_HOME}/backups`（记法 `./backups/`） | 同上 → `Env.BackupRoot` |
| 每服务版本数据目录 | `services.{kind}.{ver}.data_dir` | `{KIND_ROOT}/{version}/data` | `config.ApplyDataDirs` → `Env.DataDirFor(kind, ver)` |

- **互斥唯一**：`applyRoot` 的判据是「非空即自定义、空即回落默认」，两条路径**不并存、不叠加**；任何消费方（`internal/cache`、`internal/service/backup_service.go`、`workdir.prepareService`、`config.Env.ResolveMounts` 的 `sub=="data"` 行）都只能经 `Env` 取根，**不得自行拼 `offline/` 或 `backups/`**。
- **改根即换图**：`app.setCustomRoot` → 写 `config.yaml` → `container.Rebind(rootsKey)`。装配期分发给各门面的 `config.Env` 是**值拷贝**，不换图则缓存读写仍指旧根（选了路径却不生效）。`rootsKey` 未变则 `Rebind` 幂等直返。
- **不可自定义**：`./{kind}/{version}/ext/` 临时目录（§5.14.2，防跨任务污染必须随 PHPO_HOME）、`<用户数据目录>/`（由 OS 的 XDG 规则决定）、`www_root` 之外的站点根派生规则。
- 运行中的服务改数据目录：`root-set` 只出 `warn`（要重建容器才生效，与改端口同口径），不阻断。

## 4. 三处一致性

版本号、域名、站点根都作为路径片段参与目录/文件命名，故共享同一穿越防御：

- 版本号：见 [版本策略](./版本策略.md)（禁 `/ \ .. \x00`）。
- 域名：见 [域名策略](./域名策略.md)。
- 站点根 / 配置写 / 备份导出文件名：均先 `NormPath` + `HasTraversal`，配置保存失败自动回滚（`ConfigSaveFiles`，硬红线 3/5）。

## 5. 明确不做

- ❌ 强制站点根必须在 `WWW_ROOT` 内（允许外部，警告）。
- ❌ 允许 `..`：即使是用户主动输入也拦截（硬红线 3 无豁免）。
- ❌ 以大小写放松 Linux 敏感路径的穿越判定。
