# 用户手册

> 面向 phpo 使用者的操作手册；功能边界以 AGENTS.md 为准，界面细节见 [界面规格](./界面规格.md)，可调用能力见 [接口契约](./接口契约.md)。phpo 是面向 PHP 开发者的本地 Docker 化开发环境管理器，**仅提供 GUI，无 CLI**。

## 1. 前置条件

- 已安装并运行 **Docker**（Windows/macOS：Docker Desktop；Linux：Docker Engine）。Docker 未运行则无法启动服务（硬红线 7）。
- 首次启动进入**装机向导**：设定 `PHPO_HOME`（工作目录根，默认值 `~/phpo`）与 `WWW_ROOT`（站点根，默认值 `~/www`）。此后所有服务配置、数据、日志、备份与离线缓存都落在这两个根之下（文档里记作 `./…`，见 AGENTS.md §0.1.1）；`config.yaml` 与 `phpo.db` 则在系统的应用数据目录里，不随工作目录移动。
  - 向导打开即先**检测工作目录是否已设置**：已设置（两根已写入 `config.yaml` 且目录确实存在）时只回显当前两根与「完成」，不会再让你走一遍设置流程，也不会重复创建任何目录、文件或改写配置。
  - 「验证」是**只读预检**：只检查目录是否存在、上级是否可写，**不创建任何目录或文件**；只有点「确认并创建」（`HomeEnsure`）才会真正创建工作目录子树并落库。
  - 目录设置完成（或检测到已设置）后，phpo **第一件事就是同步权威快照**：主界面与向导弹框在同一时刻归位，无需你手动刷新，也不会出现「弹框说已设置、界面还拦着写操作」的错位。
  - 若本会话已按旧的工作目录完成初始化、刷新快照无法归位（各服务的根目录在启动时展开），phpo 会提示「正在重启应用」并按 `config.yaml` 重新拉起进程；重启过一次仍未就绪则只报错、不再重复重启。
  - 环境诊断里的「PHPO_HOME / WWW_ROOT 可写」同样只读判定：目录不存在只报错，不会顺手替你建出来。
- 装机向导之后还有**三处根可以再单独自定义**：离线缓存根、备份根、每个数据库版本的数据目录。三者都是**互斥的唯一路径**——一旦自定义，默认位置即不再使用（不会两处各存一份、也不会读一处写另一处）；清空自定义值就回到默认位置。详见 §4–§6。

## 2. 安装一个服务

1. 进入对应服务页（PHP / MySQL / PostgreSQL / Redis / Nginx）。
2. 点「安装」，输入版本号（**任意合法字符串**，如 `8.4`、`7.4-apache`；不限字符集，仅防路径穿越）。
3. phpo 先查**当前生效缓存根**下的离线缓存（默认 `./offline/`，你在「离线缓存」页改过就以你改的为准）：命中则零网络加载；未命中则先探本机 Docker 镜像库——镜像已在本机就直接导出重建缓存（同样不联网），本机也没有才联网拉取；成功后自动提升到缓存。
4. 安装即启动；卡片显示运行态。状态由后端权威推送，无需手动刷新。

> **数据服务（MySQL / PostgreSQL / Redis）安装时可填「数据目录」**：留空即用默认的 `./{kind}/{version}/data`，也可以手输绝对路径或用「浏览」选目录；同一版本改过一次即持久记住（`config.yaml` 的 `services.{kind}.{ver}.data_dir`）。这一项与默认目录**互斥、只有一个生效值**，不会两处各存一份。

> Nginx 为单例（只能装一个）；PHP 可多版本并存。

### 2.1 PHP 扩展

- **安装 PHP 时**：弹窗里的「扩展（可选）」不再是几颗示例 chip，而是**按分组铺开的当前版本全量扩展目录**（73 项 / 8 组：基础 · 数据库 · 缓存序列化 · 图像文档 · 网络消息 · 异步高性能 · 框架 C 实现 · 调试）。进入弹窗即**自动预勾选常用项**（11 个：bcmath、curl、exif、mbstring、opcache、pcntl、mysqli、pdo_mysql、apcu、igbinary、redis），你可以继续点选或取消；**一项都不选就只装基座镜像**。上面还有「过滤扩展名」「勾选常用」「清空选择」三个动作，右下角实时显示「已选 N / 目录 M」。
- **装好之后**：PHP 版本卡片上的「**管理扩展**」打开同一个选择器，**默认选中该版本当前已启用的扩展**（取自后端权威快照 `phpExtensions[版本]`，不会是空清单），改完点「应用并重建」即按你选的**完整集合**收敛——新勾选的编译并启用，取消勾选的停用，未变的不碰。
- **点「应用并重建」后弹窗立刻关闭**：这是一条要跑几十秒的后台任务，把弹窗一直钉在屏幕上没有任何用处。**进度、每一步日志与失败原因全部由日志抽屉承载**（左栏顶部的操作名 + 实时日志，右栏队列那一行的执行态），弹窗关闭不影响你在抽屉里跟全程。下次再打开「管理扩展」，默认勾选就是**上一次成功应用**的那一套（权威快照回显，不是你先前的草稿）。
- **目录里没有你要的扩展名**：下方「添加扩展」输入框可手填任意合法名字（只过路径安全/字符白名单，不做白名单限制），它会以「自定义（目录外）」分组显示并保持选中。
- **每一步都在日志抽屉里逐行看得见**：编了哪个扩展、`pecl install` 与 `docker-php-ext-enable` 的每行输出、启用了谁、停用了谁、重建镜像、重启容器。某个扩展编译失败时，**整个目标扩展集这次不应用**（用原镜像重建干净容器、撤回本次固化镜像、清空临时目录），日志里点名（`扩展 xxx 安装失败：…`）并弹出同样一句话的提醒（「扩展 xxx 安装失败，本次扩展集未应用」）——改一项再点一次即可。
- **装成功的扩展会提升到离线缓存**：固化镜像 `phpo/php:{版本}` 导出为缓存根下的第二个槽位 `php/{版本}/image-extensions.tar`（与基座镜像 `image.tar` 分开存放，**绝不覆盖基座**），并登记进 `manifest.json`。日志里有一行「已提升到离线缓存」给出完整路径。效果：**换机、清空缓存根之外的重装、断网重建容器时，带扩展的镜像仍能零网络加载回来**，不会退化成没有扩展的基座。离线缓存页每条 PHP 条目上能看到这一项是否存在。
- 部分扩展有 PHP 版本下限（如 `ffi` 自 7.4、`sodium` 自 7.2），不满足时该扩展不在目录里出现；这不影响手填。

## 3. 建站与访问

1. 「站点」页 → 添加站点：填域名（支持 `localhost`、单段名、`.test`/`.dev`/`.local` 等任意后缀）、根目录（可在 WWW_ROOT 外，会警告但放行）、选择 PHP 版本、端口。弹窗在「站点目录」下方实时回显两行宿主绝对路径：站点根目录（含容器路径）与 **vhost 文件路径** `{NGINX_SITES_ROOT}/{域名}.conf`。
2. 端口默认 80，可手动指定任意端口。**新建站点**时端口若已被占用：**不会改你填的端口**，只弹框提示，站点照常创建但处于降级态（暂不写 vhost、暂不发布端口）；腾出该端口或之后改一次端口即自动生效。**改已有站点**的端口时，占用才会自动顺延到 1–65535 首个可用端口（不报错）。
3. **建站的唯一服务门禁是 Nginx 已安装**：没装 Nginx 时无法建站（没有 nginx 就发布不了站点）。除此之外都不阻断：Nginx 已装但未运行、没装 PHP、端口被占用，都只弹框告警，站点照常创建（落库 + 站点目录 + hosts），仅暂不写 vhost、暂不发布端口。降级站点会在这些事件后**自动补齐**（`ReconcileServe`：补写缺失的 vhost → reload → 重发布端口）：安装/重建/启动 Nginx、安装或重建 PHP 版本、卸载让出端口的 MySQL/PostgreSQL/Redis、删除站点或改端口腾出端口。**Nginx 停着的时候改站点不会把它偷偷启动**——那是你主动关掉的服务；这段时间站点保持降级，等你启动 Nginx 后再一次补齐（顺带校对宿主端口，把容器上已无人使用的旧绑定一并收掉）。
4. 建站成功后立刻拉取权威快照，新站点当场出现在列表里（不等事件时序）。
5. 就绪时建站会写 vhost（写前 `nginx -t` 必过）、加 hosts、发布端口到 nginx 容器；失败自动回滚。
6. 切 PHP 版本：站点行内下拉选择，上游精确指向 `php-{版本}-fpm:9000`，切换即时生效（reload nginx）；Nginx 在运行时，降级站点也会借此补写 vhost。**注意：改端口 / 切 PHP / 伪静态 / 手改 vhost 正文这四类编辑都要把新正文写盘，而写盘前的 `nginx -t` 只能在运行中的容器里执行，所以 Nginx 未运行时会被直接拦下并提示「请先启动 Nginx 再重试」**（建站不受此限，未运行只降级）。
7. 伪静态：从 9 种预设选择，或自定义规则；高级用户可手改 vhost 正文。
8. 站点列表的 Hosts 列：已解析到 `127.0.0.1` 时显示「已解析」chip；未解析（如建站时 hosts 不可写、提权被拒）显示「加 hosts」按钮，点了才写系统 hosts。macOS/Windows/Linux 分别经 osascript admin / UAC / polkit 提权；**提权被拒只弹框转达人话警告并给出需手动添加的 `127.0.0.1 {域名}` 一行，不影响站点其他操作**（§5.7 doctor 同口径）。列表里的「健康」列与 Hosts 列都取自后端快照真值，界面不做乐观更新。
9. 编辑本站点 vhost 正文（「修改配置」→ Nginx 配置）：编辑框默认铺到主窗口高度的 80%，右下角可拖拽调整宽高。「保存并重载」先让容器跑 `nginx -t`（硬红线 2）：**校验不过会弹框列出 nginx 报错原文，线上配置已自动回滚、未重载，你的草稿仍留在编辑框里**，改完可直接再保存；ESC 只关报错弹框，不会关掉编辑器。
10. 删除站点会顺带**回收该域名的 hosts 条目**（不留指向已删站点的孤儿解析）。与建站同口径：提权被拒或 hosts 不可写时**只警告、站点照常删除**，任务日志里给出需手动删除的 `127.0.0.1 {域名}` 一行；删除任务失败回滚时条目会被重新加回。
11. **有任务在跑时站点行会标出来**：被操作的那一行在「健康」旁再显示「执行中 {步数}/{总步数}」（改端口、切 PHP、伪静态、删站、加 hosts…）或「等待中」，与服务卡片同一口径。**「正在等结果的那一颗」控件在等待期是禁用状态**（AGENTS.md §5.6.4）：切 PHP 时该行的下拉、删站时该行的删除按钮、点「立即备份」时那颗按钮、服务卡片的启/停/重建/卸载——各自只禁自己这一颗，操作收口且状态回流后自动恢复可用。**其他按钮照常可点**——并发写操作按 FIFO 排队执行，不会被整页拦下。**新建站点不点亮**：站点还没进列表（快照里没有这一行），进度看建站弹窗与日志抽屉。安装弹窗与建站弹窗在提交后自己关掉，因此不存在「等待期按钮还亮着」的问题。

## 4. 数据服务与密码

- 为 MySQL / PostgreSQL / Redis 设置**密码**：明文存储，默认 `123456`，可改、**可留空**、长度不限，UI 用 👁 查看 / 📋 复制 / ↺ 重置。**不校验**密码强度。
- 改服务端口：服务端口若被占用会报错（服务端口不自动顺延），请换一个。
- **端口与密码改完不会立刻进到正在跑的服务里**：Docker 的宿主端口发布与密码 `env` 都只在**建容器那一刻**落定，`停止`/`启动` 改不动已建好的容器。所以凡有宿主端口的服务（MySQL/PostgreSQL/Redis/**Nginx**）的版本卡片上都有「**重建生效**」按钮：它按你新存的配置重建该版本容器（等效于「卸载但保留数据卷 → 复用卷重装」），点完端口与密码才真正切换。保存端口/密码后的提示条也会告诉你要点它。
- **端口行显示的是权威值**：没改过端口时卡片显示该服务的默认宿主端口（mysql 3306 / pgsql 5432 / redis 6379 / nginx 80），与容器实际绑定的端口同源；php 不发布宿主端口（只在 `phpo-network` 内可达），该行留空。安装弹窗里按版本号顺手预填的 `33xx` 只是**预填建议**，不是你未改过时的真值。
- **有任务在跑时卡片会标出来**：被操作的那一版显示「执行中 {步数}/{总步数}」，排队中的显示「等待中」。操作按钮**不会**被禁用——写操作按 FIFO 排队执行，你可以继续点下一个。
  - 重建前会先判端口占用：**新端口被别的 service 占着就整次拒绝，正在运行的容器一根手指都没动**（不会先删了再失败）。
  - 数据卷与宿主目录（默认的 `./{kind}/{version}/data`，或你在安装时自填的数据目录）全部保留，不丢数据；重建期间该版本会短暂停止，连着它的应用会断线。
- 卸载服务默认**保留数据卷**；重装复用卷，数据不丢。
- **可以把 PHP 版本全部卸完**：没有任何「至少保留一个 PHP 版本」的门槛（AGENTS.md §1.11）。卸载只拦两种情况——该版本**根本没装**、或**库里已不成立**；剩下的都只告警放行：还有站点在用它、Nginx 还挂着它的上游，都会在确认框里点名，然后照常卸载（这些站点随即变成降级态，等你装回版本或改一次 PHP 即自愈）。同理，卸载 MySQL/PostgreSQL/Redis/Nginx 时依赖它的站点也只告警，不阻断。
- **数据目录可自定义**：安装弹窗里「数据目录」一行可手输绝对路径或「浏览」选目录，留空即用默认 `./{kind}/{version}/data`；已自定义的版本卡片上会回显当前生效路径，可以再改。**改数据目录不会搬走已有数据**——运行中的服务改这一项只警告并提示重建生效，避免把正在写的库留在原地。

## 5. 备份与恢复

- 「备份」页：一键创建备份（**逻辑导出数据服务** → 暂停数据服务 → 导出快照 → 打包 → 自动重启）。
- **备份不再被单个读不动的文件判死**：容器内的进程在宿主数据目录里留下的文件（mysql 的 `ibdata1`、pgsql 的整个 `data/`、redis 的 `dump.rdb`，以及各服务的 `logs/`）常常是宿主的你读不动的那一份。现在这类条目会被**跳过**、归档照常产出，并在日志抽屉里**按所在目录聚合**列出缺了哪些（每个目录最多列 5 项，最后一行给总数）。
- **数据库内容另有逻辑导出兜住**：备份在暂停服务**之前**，从每个**正在运行**的数据服务里把真实数据导进归档的 `dump/` 前缀——`dump/mysql-{版本}.sql`（mysqldump 全库 + 存储过程/触发器/事件）、`dump/pgsql-{版本}.sql`（pg_dumpall）、`dump/redis-{版本}.rdb`。没在跑的服务导不了，日志里会明说它只按冷拷贝打包。单个库导出失败只点名那一库，不影响其余部分入档。
- **恢复不会自动重放 `dump/`**：恢复只回放冷拷贝的内容，日志里会明确告诉你归档内有几份逻辑转储本次没有重放。异机恢复需要数据库数据时，请按库手工导入那份 SQL/RDB。
- **备份根可自定义**：页顶的备份根路径条可直接输入绝对路径，也可点「浏览」选任意文件夹；「恢复默认」即清空自定义值、回落默认 `./backups/`。归档只落在**当前生效的那一个**备份根里，不会默认目录与自定义目录并存。改根即时生效并回显（无需重启），但**有任务在跑时会被拒**（「已有任务运行中」），等队列空了再改。
- 支持下载归档（原生保存框选路径）、恢复（清空命名空间 → 解包 → 重建容器）、删除（二次确认）。
- 备份包含站点数据、配置、离线缓存与明文凭据，另含暂停**之前**先做出的数据服务**逻辑转储**（归档内的 `dump/`，mysql / pgsql / redis 各一份）——请当作敏感文件妥善保管。

## 6. 离线缓存管理

- 「离线缓存」页查看：总占用、条目数、每项镜像/apk/pecl、校验状态。
- **缓存根可自定义**：页顶的缓存根路径条可直接输入绝对路径，也可点「浏览」选任意文件夹；「恢复默认」即清空自定义值、回落 `./offline/`。**缓存根永远只有一个生效值**——你自定义后，安装时的查缓存、命中后的加载、未命中后的提升、清单 `manifest.json` 的落点、以及页面上的统计全部跟着走，不再读写默认根。**临时目录 `./{kind}/{version}/ext/` 不随缓存根移动**（它始终从 PHPO_HOME 派生，且任务结束必清空）。改根即时生效并回显，**有任务在跑时会被拒**。
- **手工导入单条缓存**（内网/离线机器的自救通道）：点「导入」→ 选服务种类与版本 → 用原生选择器选中本地已有的 `image.tar` 或扩展包（`.apk` / `.tgz`）→ 确认。phpo 把该文件**复制**进当前生效缓存根（原件留在你选的位置，不搬走），写入 `manifest.json` 与 SHA256，并在日志里给出 `cache:promote`。导入只是建缓存，**不会自动加载进 Docker**——下次安装该版本时才会命中零网络加载。文件不存在会报错，不会留下半条缓存。
- 「全部校验」重算 SHA256；损坏会提示并转入未命中分支（先探本机镜像库，再决定是否联网）。
- 清理三模式：保守（仅损坏）/ 标准（+久未使用）/ 激进（+全部，在用受保护，涉删二次确认）。
- 换机/内网三种做法：① 在目标机的「离线缓存」页把缓存根**改成指向同一份既有缓存目录**；② 整目录搬运后改根（默认根是 PHPO_HOME 根下的 `./offline/`，根位置可在装机向导「已设置」回显或快照 `env.PHPO_HOME` 查看）；③ 单条文件用上面的「导入」。

## 7. Docker 清洁与回收站

- 「清理」页：扫描孤儿资源（容器/卷/网络/镜像），按三模式清理。
- 回收站：删除的站点根目录保留 **7 天**，可一键恢复；到期后彻底删除。
- 操作审计：设置页可查最近操作历史（`<用户数据目录>/logs/operations.log`（Linux `~/.config/phpo/logs/`））。
- **「同步状态」是全量比对，不只比运行态**（侧栏按钮与 ⌘R 命令面板是同一个入口）。它会拿库里记着的每一版服务去宿主核对三样东西：**容器**（`phpo-{kind}-{version}`）、**该版本应运行的镜像**（装了扩展的 PHP 以 `phpo/php:{版本}` 为准，没装才看官方基座）、**扩展固化镜像**。你在 Docker Desktop 里或用 `docker rm` / `docker rmi` 删掉的东西，这里一律会认出来。
- **认出缺席 ≠ 替你决定**：缺失只**标记 + 点名**，不会自动把该版本改成「未安装」、不会自动删记录、也不会偷偷重建容器。因为配置、数据卷、离线缓存都还在——**点「启用」就按当前配置幂等重建回来**。界面上的表现：服务卡片上多一枚黄色「{原因}缺失」标记（鼠标悬停说明是哪一样不在了、以及点启用会怎么做），日志抽屉左栏逐条列出每个缺失项；没有缺失项时只回一行汇总。
- 校准是**幂等**的：宿主没变化时不会重复推事件，所以反复点「同步状态」不会把日志刷成同一行。

## 8. 诊断（doctor）

- 「总览」页 doctor 一键体检 15 项：Docker 可用/版本、端口、目录可写、hosts 权限、网络、缓存完整性、临时目录残留等。
- 可修复项提供一键操作：状态校准（`calibrate`）、清空临时目录残留（`clear_temp`）。多数非致命问题以**警告**呈现，不阻断使用（最小限制原则）。

## 9. 检查更新与升级

- 启动时 + 每 24 小时自动检查更新，也可在设置里手动检查。
- 有新版本时弹窗提示；升级包经 SHA256 + 数字签名双校验后安装，失败自动回滚到旧版本。

## 10. 外观与偏好

- 6 套主题、中/英双语、7 档界面缩放；这些偏好只存本机（`localStorage`），不影响后端状态。
- 命令面板（20 条命令）与系统托盘提供快捷入口。**全界面都不显示「等效命令」**（AGENTS.md §1.4）：本产品只有图形界面、没有命令行，所以界面上任何位置都不会出现一行看起来能照着敲的 `phpo …` 文本——日志抽屉头部没有，「安装服务」「新建站点」「危险确认」三类弹窗里原来那行「将执行 $ phpo …」预览也一并去掉，装机向导的验证日志与演示模式的回放日志同样不再以命令行开头。你要确认的信息改由更直观的形态给出：弹窗里的**表单字段与路径**（站点根目录的宿主路径 → 容器路径、vhost 落盘路径）、危险确认里逐条列出的**警告文字**、以及队列里那行**人话标签**（如「删除站点 demo.test」）；任务的详细过程始终在左栏日志里逐行给出。（服务页「伪静态」预览、安装弹窗里的挂载表这类等宽方块显示的是真实路径与配置内容，不是命令，照旧保留。）
- **日志抽屉是左右两栏**：**默认** 左边 70% 是**当前这件事的名字** + 它的进度、失败原因与实时日志，右边 30% 是任务队列。左栏最上方那行加粗文字就是操作名（如「创建备份」「停用 PHP 8.4」「删除站点 demo.test」），你点开抽屉第一眼就知道在跑哪件事——它取自后端的权威任务标签，不是前端拼的文案；没有选中任务（显示系统日志流水）时这一行不出现。抽屉头部三区不变：左上角标签固定显示「**服务**」，不随所在页面变化，操作名因此摆在日志栏内而不是头部（AGENTS.md §5.6.1 / §5.6.4）。中缝可以**按住左右拖拽**调整占比（日志栏在 40%–80% 之间夹取，队列栏补足剩余），**双击中缝回到默认 70/30**；这个比例只存本机 `localStorage`，不影响后端状态。
- **队列里最新提交的任务永远在最上面**，一行一个任务，标明它现在是**等待中 / 执行中 / 已完成**（失败、已取消也会如实标出）。任务一提交就立刻出现在队列里，不用等它开始执行；「等待中」的行可以点「撤回」，撤回后那一行随下一次同步消失。
- **没有任务在跑时，左栏显示系统日志**：缓存命中/未命中/提升/损坏/清理/临时目录清空、Docker 清理与孤儿发现、状态漂移、发现新版本与升级完成等后端事件会**实时逐行**滚进来（最多留最近 200 行，更早的随内存裁掉）。有任务在跑时这类事件归属到该任务的日志里。这些是**事件流水不是任务**——不进任务队列、不计入任务状态、也不写操作账本。启动后还没有任何事件时显示空态提示。
- 设置页的「显示托盘图标」「关闭窗口时最小化到托盘」即时生效：两者都勾选时，点窗口关闭按钮只是收进托盘（点托盘图标唤回）；关掉任一项，点关闭即退出应用。「显示托盘图标」在 Linux 上只影响驻留判断与窗口内托盘，撤下系统图标的这一步 Wails 当前版本尚未支持。

## 11. 常见问题

| 现象 | 处理 |
|------|------|
| 启动报「服务尚未初始化」 | 等待初始化完成或先走装机向导 |
| 已有任务运行中 | 排队或点「取消」（取消会回滚并清临时目录） |
| 端口被占 | 新建站点：仅提示，站点以降级态创建（暂不发布端口），腾出端口或改一次端口即恢复；改站点端口：自动顺延；服务端口：换值重试 |
| 装不上（内网/断网） | 确认对应版本已在**当前生效缓存根**的离线缓存中；手上有 `image.tar`/扩展包但没有缓存条目时，用「离线缓存」页的「导入」把它登记进缓存；既未缓存、本机 Docker 里也没有该镜像，离线环境装不了 |
| 改了缓存根/备份根/数据目录像没生效 | ① 先看路径条显示的是不是你以为的那个值（chip「自定义」= 已生效，无 chip = 仍在默认根）；② 队列里有任务在跑时改根会被直接拒（「已有任务运行中」），等队列空再改；③ 数据目录要**重建该版本容器**才换挂载，页面上会警告 |
| 点「启用」报「运行态校验失败：期望 running=true，实际 false」 | 容器被拉起但**进程自己退了**（典型是 pgsql 往宿主日志目录写日志文件被拒 → FATAL 崩溃循环）。现在这一项在「启用」时**自愈**：仍是旧默认写法的 `postgresql.conf` 会被就地改回「日志走标准错误」，日志里给一行说明已修复；已被你自己改过的配置不会被动，只提示核对。若仍失败，报错里会带**退出码与容器日志尾部 5 行**，按那句处理即可 |
| 备份报「open …/logs/access.log: permission denied」 | 已不再是致命错误：该条目被跳过、归档照常产出，日志里按目录聚合列出缺了什么；数据库内容由 `dump/` 的逻辑导出兜住（见 §5） |
| 想彻底重来 | 清理页激进清理（保留卷）或删卷前二次确认 |
| 用 Docker Desktop / `docker rm` 删过容器和镜像，列表却还说「已安装」 | 点侧栏「同步状态」（或 ⌘R）。它会比对容器、基座镜像、扩展固化镜像三样，缺的逐条点名并在卡片上标黄；**它不会自动把版本改成未安装**，因为配置/卷/缓存都还在——点「启用」即按当前配置重建回来 |
| 「应用并重建」扩展后弹窗一下就没了，以为没执行 | 正常：提交即关窗，任务在后台跑。进度与每一步日志在**日志抽屉**（左栏顶部的操作名 + 实时日志，右栏队列的执行态与终态）。重开「管理扩展」时默认勾选就是权威库里已应用的集合 |
| 想让多个用户/容器都能读写 phpo 建出来的目录和文件 | 已经是了：phpo 自己的产出物一律 `0777`（见 §12）。数据目录里由容器内进程写出的文件不在其列，那是另一个 uid 的产物 |

## 12. 文件与目录权限

- **phpo 自己建立的目录与文件权限一律 `0777`**（AGENTS.md §5.20）。本产品面向程序员，不替你限制文件访问：`<用户数据目录>/` 里的全部（`config.yaml`、`phpo.db`、审计日志、回收站、升级工作区）、PHPO_HOME 下 phpo 建的目录与文件（vhost 配置、渲染出的服务配置、离线缓存的 `image.tar` / `image-extensions.tar` / `manifest.json`、临时目录、备份归档 `.tar.gz`）都按 `0777` 归一。旧装机留下的 `0755`/`0644` 会在下一次写入时自动修好。
- **不越界**：容器内进程写出来的文件（`./mysql/{ver}/data/*`、`./pgsql/{ver}/data/*`、`./redis/{ver}/data/dump.rdb`、宿主 bind 目录里的 `logs/*.log`）与站点根里你自己的源码，phpo 不会去 `chown`/`chmod`——那是另一个 uid 的产物，改它等于擅自动你的环境。备份碰到这类读不动的文件时按「跳过并聚合告警」处理（见 §5），不会强行改权限。
- **配套口径**：密码本来就是明文存储、UI 可查看、不加密（§4），因此 `config.yaml` 世界可读是这条策略的既定代价；本产品不引入任何加密、keyring 或密码强度限制。多用户共享机器或需要保护凭据时，请自行用磁盘加密或隔离账户。
