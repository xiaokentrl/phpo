# 目录规范

> 对应 AGENTS.md §3.1（工程布局六原则）/ §4.1（目录结构树）/ §4.2（运行时用户数据目录）/ 工单 T704。自总纲 **v2.9.3** 起，§4.1 目录树已按**仓库当前真实布局**重写，本文与其一致；仍缺的规划交付物见 §8。冲突最终以 AGENTS.md 为准。

## 1. 工程布局六原则（§3.1）

1. **根目录一眼看懂**：入口文件、配置、中文文档置顶。
2. **内部严格分层**：装配 → 配置 → 模型 → 存储 → 引擎 → 模板 → 校验 → 任务 → 服务，单向依赖（硬红线 §0.2-12）。
3. **中文注释全覆盖**：每个文件、目录用一句中文说明。
4. **模板内聚**：配置模板以 `go:embed` 嵌入 `internal/template/templates/`。
5. **UI 偏好留前端**：主题、语言、布局、缩放用 `localStorage`，不落后端。
6. **命名见名知义**：文件名与原型函数名对齐（见 §6 映射表）。

## 5. frontend/ src 分层

`api/`（17 绑定封装：env lifecycle site extension config backup offline cache doctor task state updater cleanup wizard docker events + mockEvents）· `stores/`（Pinia 8：appState taskStore layoutStore prefsStore updaterStore cleanupStore cacheStore modalStore）· `composables/`（use* 15）· `views/`（12 个 .vue = 11 路由视图 + `ServiceView.vue` 共用基座）· `components/`（`common/` 9（含 `ExtPicker.vue`：PHP 扩展全量目录选择器，安装弹窗与管理扩展弹窗共用）+ `business/` 19）· `constants/`（9）· `locales/`（index / zh-CN / en-US）· `styles/`（base.css + 6 主题）· `types/` · `utils/`（4）· `router/`。`bindings/` 由 `wails3 generate bindings` 生成（gitignore），`dist/` 为构建产物，但 `dist/index.html` 是 tracked 占位文件，构建后需 `git checkout -- frontend/dist/index.html` 还原。正因为 `bindings/` 不入库，`pnpm build` 不得先于生成它执行——`Taskfile.yml` 的 `frontend:build` 已声明 `deps: [bindings]`（见 [打包发布](./打包发布.md) §2）。

## 6. 其余顶层目录

- `build/`：三平台打包资源（`appicon.png`；`windows/{icon.ico,wails.exe.manifest,nsis/installer.nsi}`；`darwin/{icon.icns,Info.plist,entitlements.plist}`；`linux/{phpo.desktop,nfpm.yaml,postinstall.sh,icons/*}`；`bin/` 为 gitignore 产物）。签名公钥不在 `build/signing/`，改由 `internal/updater/signing/public.key` 经 `go:embed` 随包分发。
- `scripts/`：五项门禁 `check-{i18n-keys,templates,docker-naming,cache-manifest,ext-catalog}.go`（`ext-catalog` 对账 `frontend/src/constants/ext.ts` 的 `tool` 与 `internal/config/extensions.go` 的 `peclExts`）；发布辅助 `sign-release.sh` `gen-checksums.sh` `verify-signing-guard.sh`；版本 `bump-version.sh` `version.sh`；`gen-locales.mjs`（会重写 locales，谨慎执行）。dev/build/bindings/打包统一走 `Taskfile.yml`。
- `docs/`：全中文文档 32 篇（§11.2 清单，本目录）。
- `test/`：仅 `integration/`——10 个真环境 live 用例（含 `g4_pgsql_heal_live_test.go`：旧版 `postgresql.conf` 裸启动必失败且报错带日志取证 → 经 `AppService.Start` 自愈后就绪），由 `PHPO_LIVE=1` + Docker 可用双重 skip 守护；单元测试与包同目录（80 个 `*_test.go`，fake/mock 内联）。
- `third_party/licenses/`：第三方许可证清单。
- `.github/`：`workflows/{ci,lint,release}.yml` + ISSUE/PR 模板。

## 7. 运行时用户数据目录（§4.2）

> **记法**（AGENTS.md §0.1.1）：`<用户数据目录>/` = `os.UserConfigDir()/phpo`，位置由 OS 决定；`./` = **PHPO_HOME 根**，由装机向导写入 `config.yaml` 的 `phpo_home`，打包安装后可在任意磁盘/任意路径，`~/phpo` 只是默认值——两者不同源，勿混用。

```
<用户数据目录>/       # = os.UserConfigDir()/phpo（Win: %APPDATA%\phpo · mac: ~/Library/Application Support/phpo · linux: ~/.config/phpo）；由 OS 决定，不受装机向导影响
├── config.yaml   phpo.db            # config.yaml = 单一配置权威（根目录 + 明文密码 + 端口，0600）；phpo.db = SQLite 仅存运行态（延迟建库）
├── logs/operations.log              # JSON Lines 审计（§5.13.10）
├── trash/                           # 回收站，保留 7 天
└── updates/{downloads/, backups/}   # 升级工作区

./                  # PHPO_HOME 根（= config.yaml 的 phpo_home，装机向导可指向任意目录；`~/phpo` 仅默认值）
├── php/<ver>/{conf,logs}          # + ext/（临时目录，任务结束即清空，§5.14.4）
├── nginx/{conf,logs,sites/}
├── mysql/<ver>/{conf,data,logs,initdb}
├── pgsql/<ver>/{conf,data,logs,initdb}
├── redis/<ver>/{conf,data,logs}
├── backups/backup-*.tar.gz
└── offline/        # 离线缓存根（持久，§5.14.2）
    ├── php/{ver}/{image.tar, apk/, pecl/, manifest.json}
    └── {mysql,pgsql,redis,nginx}/{ver}/{image.tar, manifest.json}

~/www/              # WWW_ROOT（默认，可改）

# Docker 资源命名（§5.13.2）：容器 phpo-{kind}-{version} · 网络 phpo-network · 卷 phpo-{kind}-{version}-{purpose}
```
