# 目录规范

> 对应 AGENTS.md §3.1（工程布局六原则）/ §4.1（目录结构树）/ §4.2（运行时用户数据目录）/ 工单 T704。本文以**仓库当前真实布局**为准；与 §4.1「目标树」不一致处以本文「与总纲目标树的差异」一节说明，冲突最终以 AGENTS.md 为准。

## 1. 工程布局六原则（§3.1）

1. **根目录一眼看懂**：入口文件、配置、中文文档置顶。
2. **内部严格分层**：装配 → 配置 → 模型 → 存储 → 引擎 → 模板 → 校验 → 任务 → 服务，单向依赖（硬红线 §0.2-12）。
3. **中文注释全覆盖**：每个文件、目录用一句中文说明。
4. **模板内聚**：配置模板以 `go:embed` 嵌入 `internal/template/templates/`。
5. **UI 偏好留前端**：主题、语言、布局、缩放用 `localStorage`，不落后端。
6. **命名见名知义**：文件名与原型函数名对齐（见 §6 映射表）。

## 5. frontend/ src 分层

`api/`（15 绑定封装）· `stores/`（Pinia 8）· `composables/`（use* 14）· `views/`（11）· `components/`（layout/common/business）· `locales/`（zh-CN/en-US）· `styles/`（6 主题）· `router/`。`bindings/` 由 `wails3 generate bindings` 生成，`dist/` 为构建产物（均不入库）。

## 6. 其余顶层目录

- `build/`：三平台打包资源（`windows/nsis/installer.nsi`、`darwin/`、`linux/nfpm.yaml`、`signing/public.key`、图标）。
- `scripts/`：`check-i18n-keys.go` `check-templates.go` `check-docker-naming.go` `check-cache-manifest.go` `sign-release.sh` `gen-checksums.sh` `gen-locales.mjs`。
- `docs/`：全中文文档（§11.2 清单，本目录）。
- `test/`：`unit/ integration/ e2e/ fixtures/ mocks/`。
- `third_party/licenses/`：第三方许可证清单。
- `.github/workflows/`：`release.yml`（一键出包）。

## 7. 运行时用户数据目录（§4.2）

```
~/.phpo/            # 用户数据目录（Win: %APPDATA%\phpo · mac: ~/Library/Application Support/phpo · linux: ~/.config/phpo）
├── config.yaml   phpo.db            # config.yaml = 单一配置权威（根目录 + 明文密码 + 端口，0600）；phpo.db = SQLite 仅存运行态
├── logs/{phpo.log, operations.log}   # operations.log = JSON Lines 审计（§5.13.10）
├── themes/ locales/ trash/            # trash 保留 7 天
└── updates/{downloads/, backups/}

~/phpo/             # PHPO_HOME
├── php/<ver>/{conf,logs}          # + ext/（临时目录，任务结束即清空，§5.14.4）
├── nginx/{conf,logs,sites/}
├── mysql/<ver>/{conf,data,logs,initdb}
├── pgsql/<ver>/{conf,data,logs,initdb}
├── redis/<ver>/{conf,data,logs}
├── backups/backup-*.tar.gz
└── offline/        # 离线缓存根（持久，§5.14.2）
    ├── php/{ver}/{image.tar, apk/, pecl/, manifest.json}
    └── {mysql,pgsql,redis,nginx}/{ver}/{image.tar, manifest.json}

~/www/              # WWW_ROOT（默认，可改）

# Docker 资源命名（§5.13.2）：容器 phpo-{kind}-{version} · 网络 phpo-network · 卷 phpo-{kind}-{version}-{purpose}
```

## 8. 与总纲目标树（§4.1）的差异

以下 §4.1 目标节点在实现中**尚未落地或以等价形态存在**（属命名/落点调整，不改变行为契约）：

- `internal/i18n/`、`internal/store/` 无独立 `snapshot.go` 之外的 `trash.go` 等仍齐备；`internal/task/cancel.go` 未单列（取消由 `manager.go` + `context` 承担）。
- `internal/service/`：`task_service.go` `state_service.go` `prefs_service.go` 未建；UI 偏好按 §3.1-5 留在前端 `localStorage`，任务/状态经 `app_service.go` + 事件总线路由。
- `internal/task/steps/`：仅 `steps_{service,site,config,update}.go` 存在；`steps_{home,extension,backup,offline,cleanup}.go` 的能力内联于对应 service，未单拆步骤文件。
- `internal/engine/`：无 `snapshot.go`；以 `inspect.go` + `calibrate.go` 承担快照/漂移。
- `pkg/`：无 `execx/ fsutil/ hash/`；命令执行用 `internal/engine/exec.go`，SHA256 用 `internal/cache/verifier.go` + `internal/updater/verifier.go` 标准库实现；`disk/` 为新增。
- 根：`README*.md CHANGELOG.md CONTRIBUTING.md LICENSE`、`configs/ assets/ data/`、`.github/workflows/{ci,lint}.yml` 未落地。
