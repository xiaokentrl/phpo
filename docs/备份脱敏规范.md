# 备份脱敏规范

> 对应 AGENTS.md §5.13.11–12（导入/重装）/ §5.14.9（缓存迁移）/ §1.5（密码明文）/ §11.2 / 工单 T704。定义备份归档的**内容边界**。冲突以 AGENTS.md 为准。

## 1. 归档内容清单（`backup_service.go#backupSources`）

| 纳入 | 说明 |
|------|------|
| PHPO_HOME 五服务目录 | `~/phpo/{php,nginx,mysql,pgsql,redis}/<ver>/{conf,data,logs}` |
| WWW 站点 | 站点根目录内容 |
| SQLite 快照 | 运行态物化（`store.BackupTo` VACUUM INTO；仅 installed/running/sites/extensions/trash/operations 等，**不含 `dir_ready`**——该表已在迁移 0007 下线） |
| 离线缓存 | `~/phpo/offline/`（支持换机后零网络重装，§5.14.9） |
| `config.yaml` | 单一配置权威（根目录 + 明文密码 + 端口），随包携带，恢复时一并落回并重载 |

| 排除 | 说明 |
|------|------|
| **Docker 镜像本体** | 不打进 tar.gz；镜像靠离线缓存/重装重建（原型 restore warn4） |
| 临时目录 `ext/` | 任务结束必清空，本不应存在（§5.14.4） |

归档命名：`backup-YYYYMMDD-HHMMSS.tar.gz`，落 `~/phpo/backups/`；顶层内容组数即 `model.BackupFile.items`。

## 2. 「脱敏」的边界（重要澄清）

本项目的「脱敏」指**排除可重建的大体积 Docker 镜像层**，**不含**凭据遮蔽：

- 密码在本项目为**明文策略**（§1.5 / §0.2-5：默认 `123456`、可空、长度不校验、**禁止加密/keyring**）。
- 因此 `config.yaml`（含数据库/Redis 明文密码）**原样**随归档打包，恢复时明文落回并经 `ConfigStore.Reload` 热重载（`backup_service.go#materialize`，用户裁决）。
- 不得引入 bcrypt/AES/keyring 等对备份内容做加密或哈希（违反 §1.5）。

> 提示：备份包含明文凭据 + 站点数据，属敏感归档；迁移/分享时应按普通敏感文件对待（文件系统权限、传输信道由用户掌控）。此为使用注意，不改变归档行为。

## 3. 创建流程（§5.13，三段式）

```
BackupCreate → 暂停数据服务 → 导出 SQLite 快照 → archive.Create tar.gz
            → 自动重启暂停过的服务（restartStep，原型 backup.warning）
            → applyStateChange + emit state:changed
```

全程硬红线 5（三段式）+ 硬红线 4（后端权威广播）；失败回滚不留半成品归档（写盘用 `MkdirTemp` 临时目录，成功后落 `BackupRoot`）。

## 4. 恢复流程（异机口径，§5.13.11）

```
BackupRestore(file) → 清空 phpo 命名空间 → 解包落盘（含 config.yaml，明文密码）
                   → 逻辑重放 SQLite → 重建容器（优先命中离线缓存，零网络）
                   → emit state:changed
```

- 清空目标命名空间后再恢复（幂等，§5.13.13「导入不清空」为禁止项）。
- 默认**保留卷**语义：恢复以归档内容为准；删卷需二次确认（[回收站机制](./回收站机制.md)）。

## 5. 路径安全（硬红线 3）

- `BackupPath(file)` / `BackupSaveAs(file, dst)`：`file` 仅接受合法归档文件名（禁 `..`/分隔符），防目录穿越。
- `Delete(ctx, file)` 同样先做文件名安全校验（[路径策略](./路径策略.md)）。

## 6. 删除与前端确认

`BackupDelete` 删除归档；二次确认在前端（`DangerConfirm`）。列表按时间倒序、后端权威（`BackupList`）。
