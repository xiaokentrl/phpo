# 版本策略

> 对应 AGENTS.md §1.6 / §5.4 / §0.2-7 / 工单 T704。**不限制任何服务的版本号字符集**，仅做路径安全校验。冲突以 AGENTS.md 为准。

## 1. 唯一保留的校验规则（§5.4）

`ValidateVersion(kind, version)`（`internal/config/versions.go`）逐条对齐原型 `validateVersion`（SSOT:1658）：

| 规则 | 实现 |
|------|------|
| 非空 | trim 后为空即非法 |
| 无 `/` `\` | `ContainsAny(v, "/\\")` |
| 无 `..` | 独立 `..` 段检测（`reTraversal`） |
| 无 `\x00` | `ContainsRune(v, 0)` |
| 无控制字符/空白 | `hasWSOrCtrl`（`[\x00-\x1f\s]`，含 Unicode 空白，与 JS `\s` 对齐） |
| 长度 ≤ 128 | `MaxVersionLen = 128`（§0.3 权威值） |
| 首尾 trim | `strings.TrimSpace` 后判定 |

`kind` 参数保留自原型签名，当前不参与判定。

## 2. 明确禁止（§0.2-7、§2.1）

- ❌ 版本号字符集白名单（不做 semver 强制、不限制前缀/后缀）。
- ❌ 限制「只允许某几个版本」——版本开放输入，任意合法字符串（如 `8.4`、`8.4.1`、`nightly-2026`、`7.4-apache`）均可。
- ❌ 服务版本上下界限制。

> 例外：`pkg/version/semver.go` 的 SemVer 比较仅用于**升级检查**的版本先后判断（应用自身版本），不用于服务版本号裁决。

## 3. 落地

- 校验入口：`internal/config/versions.go` `ValidateVersion` → `VersionCheck{Ok, Value, Msg}`，失败文案 `errs.VersionInvalid`。
- 容器/镜像命名：版本号原样保留（含点），映射 `phpo-{kind}-{version}`、上游 `php-{version}-fpm:9000`（硬红线 1，见 `docs/PHP切换准确性.md`）。
- 缓存目录：`./offline/{kind}/{version}/`（`./` = PHPO_HOME 根，装机向导选定，非固定 `~/phpo`）；版本号原样即目录名，仅因上面的路径安全校验保证不穿越。
- UI：`InstallModal.vue` 版本输入仅即时反馈，最终裁决在后端 preflight（§0.2-14）。

## 4. 与路径安全的一致性

版本号既是标识又是路径片段，故版本校验与 `docs/路径策略.md` 的穿越防御共享同一原则：禁止 `/` `\` `..` `\x00`。二者共同支撑硬红线 3。
